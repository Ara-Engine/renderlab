# M4 execution: legal detail cuts and bounded geometry residency

Authorized by Islam's M2–M4 request. M3 is accepted with its sampler correction; M4 is in progress, with no runtime streaming implemented yet. This specializes the already reviewed [M4 contract](m2-m4-design.md), rather than reopening the engine architecture. Pstack implementation uses Sol at xhigh; root owns design, verification and publication, with Opus reserved for consolidated acceptance. Stop after M4.

## Throughput and units

- Blocking first step: reproducible dense fixtures, owned hierarchy/page metadata and CPU proofs of legal replacement. Runtime streaming cannot repair an invalid cut representation.
- Independent implementation streams: none initially. The cluster cooker, prepared format and cut oracle must agree on group identity and page ownership. Read-only review can be separate.
- Shared mutable state: one implementation owner per unit. Root owns plan/milestone documents. Builds, GPU runs and source-mutating measurements remain serialized; two Cargo jobs.
- Smallest safe decomposition: A prepares data and proves selection; B integrates bounded asynchronous page IO, GPU retirement and viewer behavior; C runs registered exhaustion/image/performance experiments, fixes failures and obtains acceptance. Push validated checkpoints between units.

## Unit A: fixtures, cooking and cut proofs

Keep meshopt 0.7.0 / meshoptimizer 1.3 in the cooker only. Check and preserve the actual wrapper/upstream licenses before adopting the source; record added packages and build cost. Use the safe clusterlod callback API and copy borrowed indices/metadata before callbacks return. Do not enable unsupported border dilation. Preserve full-precision positions and normal/UV/color/material boundaries with explicit attribute weights, seam protection and pinned settings; avoid sloppy fallback as a silent quality escape.

Create deterministic self-authored dense fixtures, including a closed curved surface for watertightness checks and a distinct material/thin-feature case. Use the existing prepared asset as the full-detail reference. Each streaming fixture's full-detail geometry must exceed four times its declared normal geometry pool; start with an 8 MiB pool or roots plus four pages, whichever is larger. Choose density inside the existing admitted source/prepared limits, or explicitly justify a bounded cooker-only limit change. A subdivided closed cube/sphere and a curved sheet with attached thin details are suitable starting shapes; they are not permission to import artwork.

Before implementing the bounded-selector experiment, save a registration artifact with generator source/settings, source/prepared SHA-256, material/texture identity and explicit 1080p camera trajectories (overview, approach, sweep, abrupt cut, return and 300 settled frames). Hash the camera record too. Preserve that initial registration. Any later fixture/settings change gets a new identity and reason, not replacement of failed evidence. Root carries the registered hashes into the tracked milestone record before GPU experiment implementation.

Use a dependency-free prepared representation that distinguishes clusters, replacement groups and IO pages. A cluster records its owning group, refined group or original-leaf marker, bounds, material and page-local index range. Groups carry upstream accumulated simplified bounds/error and replacement dependencies. Terminal groups can occur at shallow levels; the spatial hierarchy is not replacement ancestry. Material and shared-position seams must retain their interpretation across independently cooked subsets.

Pack actual page-local vertices and indices into immutable pages, initially 64 KiB. No full-detail GPU vertex buffer may remain pinned as a substitute for paging. Prefer packing fallback clusters together so root residency is explicit. Record payload lengths/digests, bounded offsets/ranges, root pages, total geometry bytes and metadata size; distinguish payload bytes, duplicated boundary vertices, disk padding and runtime allocations. Validate counts, references, acyclicity, ranges, numerical values and aggregate budgets before allocation/use. The M3 standalone format can remain intact beside a separately versioned virtual package; runtime never imports the cooker or glTF/codecs.

Build one pure selection function over metadata and currently published pages. Start with all terminal coarse cover and replace every shard of a group together. Compute dependency closure when an intended refinement spans owners; final publication must remain legal. Missing-page demand and the transition's required cover must agree: never wait for intermediate pages that were not requested. Report denied projected error and missing demand as quality debt. Budget/candidate/output exhaustion preserves the current complete legal cover instead of emitting a partial refinement.

CPU proofs precede GPU integration: chain, shared-owner, shallow-terminal and diamond cases; exhaustive small cuts; exact-once structural coverage; no unpaired positional edges for closed fixtures (with explicit seam welding interpretation); unlimited availability equals clusterlod's documented group-error rule; finite budgets/candidate/output limits never lose the minimum cover. A simple independent oracle must not call the optimized selector. Test failures, invalid metadata and incomplete availability, not only the happy path. Projection error is an approximation; conservative transform scale/near handling and later images are still necessary.

Unit A acceptance is CPU/cooker evidence only: deterministic cached preparation and corruption/invalidation behavior, actual hierarchy/page counts/bytes, proof results, package/camera hashes and dependency/build-boundary checks. It does not certify streaming, GPU memory, image quality or M4 completion.

## Unit B: runtime and resource lifetimes

Unit A is accepted with root reproduction recorded in [milestone-4.md](milestone-4.md), including the fixed registered content and camera hashes. The blocking proof/cooking phase is complete. Unit B remains one coupled implementation stream: page state, submission completion and cluster draw ranges share ownership invariants. Root owns independent verification and publication; a fresh Sol implementation owner handles the runtime migration. CPU state-machine checks precede offscreen GPU integration and real IO/retirement stress; root then verifies live interaction and Unit C measurements.

Caller-owned virtual geometry shares demand/residency per asset; cuts are per instance. Integrate page-local cluster draw ranges with the existing material/instance path and ordinary hardware rasterization. Preserve M3's optional 4x AA, shader recovery and library/window separation. Virtual geometry may declare a supported affine transform domain; it must not silently weaken raw M2/M3 APIs.

Use explicit bounded page states for queued read, ready bytes, admitted upload, resident and retiring work. File reads happen off the render thread. Failed or corrupt reads retain fallback, report errors and avoid unbounded retries. Demand order is deterministic at a fixed view; selected or demanded pages are not self-evicted. Publish legal cuts from currently usable pages. Ordinary frames never wait for IO or GPU completion.

One logical geometry budget charges pinned fallback, resident pages, resources awaiting their last GPU use, and upload staging. Account actual page buffer sizes and padding; admission needs headroom before allocation. Device/driver memory observations are separate from that logical bound. Enforce a minimum-cover and minimum-output-capacity check for every admitted instance, including offscreen instances. Separate caps are four pending 64 KiB reads, two page uploads/frame, 8 MiB metadata/scratch and 64 MiB textures. Shared asset pages are charged once. Explicitly bound CPU retained payloads and pending requests too.

Completion tracking must retain replaced/evicted buffers until their last submission completes, while charging them to the same pool. Tests must show incomplete prior work during replacements and bounded peaks across waves; resize-induced GPU draining cannot supply the only lifetime evidence.

## Unit C: registered exhaustion experiment and acceptance

The selected extension is inspectable covered fallback under candidate/output/residency exhaustion, with per-frame quality debt. It addresses a documented class of capacity failures; it is not an established advantage over current Nanite without equivalent-content execution of a specified Unreal build. Keep current capability caveats from the [grounding/design](m2-m4-design.md).

Run candidate capacities 1/64/1024, output minimum plus 0/64/4096, below-minimum rejection, 0/100 ms artificial IO delay, actual read failure/corruption, traversal/cuts/revisits and 300 settled frames. Every admitted configuration must retain coverage and obey all budgets, and settled selected pages must not reread. Compare the same cooked DAG with the simple legal selector at equal total budgets and full-detail images.

At normal budget target silhouette p99 <= 1 pixel, maximum <= 2 pixels and interior material-ID disagreement <= 0.1% at 1080p, with no unexplained cracks/depth discontinuities. Verify normals/UV/material continuity and actual moving frames. Forced-minimum quality loss is reported separately with debt; thresholds are not weakened to hide a failed normal-budget case. Root inspects complete images and viewer interactions, including resize/minimize and malformed/corrected shader reload during streaming.

Measure cold cooking, warm reuse, changed-input recooking, startup/upload, Rust/shader development latency, CPU preparation/selection/IO/admission/encoding, GPU execution, acquisition/presentation, bytes/read/upload/retirement/churn and peak owned/HAL/allocator observations. Record exact source/executable/package/camera identities, hardware, profile, quality and contention. Keep validation-on correctness separate from optimized timings. Preserve failures and limitations, obtain independent acceptance, commit/push as Snowy7 and stop after M4. No GI, advanced lighting, transparency, topology-edit system or custom rasterizer is authorized by this plan unless a concrete M4 acceptance failure requires a scoped change.
