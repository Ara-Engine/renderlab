# M7 U1: specular filtering

Implementation branch `t3/m7-u1`, based on `ecb595c`, 2026-11-07.
**U1 is incomplete. The isotropic candidate fails the static and F3 gates on both
paths and is not a default.** The data preparation and shader helpers are retained
for explicit experimentation. No quality or performance superiority is claimed.

The cook retains the length of the unnormalized normal mean through the mip
chain, including cancelled means and odd edges. RLA v3 adds texture role 3,
`NormalVarianceLinear`: unit XYZ in linear RGB and RMS spread
`sqrt(clamp(2*(1-L)/L,0,1))` in A. This uses the existing RGBA8 allocation.
Opt in with cook `Settings { normal_maps:true, normal_variance:true, ..Default::default() }`,
or `renderlab-cook cook ... --normal-maps --normal-variance`.
The experimental recipe and cache namespace are `normal-v3`; RLA v1 and v2 and legacy
normal role 2 keep their meaning. RVG remains v2, with nested RLA v3 resources;
its cache recognizes the extended input schema. Geometry sidecars do not change.
Plain `--normal-maps` retains the previous normalized-mip recipe, cache key and
`normal-v2` namespace. New variance mips can change RGB direction beyond mip 1
because they propagate the true first moment; this is an explicit content change
only when opting into v3. GPU bytes remain four per texel; the cooker retains an
additional four-byte mean length per floating-point mip texel.

`filtered_roughness(roughness, variance)` adds variance to squared GGX alpha,
then maps back to perceptual roughness. The standard program has
`const SPECULAR_AA:bool=false`. Set it true in an explicitly selected program to
use the same filtered roughness for direct light, DFG and environment sampling. Custom
programs opt into this helper, or consume the geometric normal differentials
without adopting GGX. Receiver/hit records and dispatch structure are unchanged.

The normal-map helper squares A, adds within-level RGB direction cancellation
with a 0.008 UNORM quantization dead zone, and applies normal scale squared.
These are isotropic, small-slope approximations: large/negative scales,
anisotropic or multimodal distributions are not exactly represented. The stored
spread saturates at one. Bilinear interpolation of RMS spread is approximate.
Legacy maps cannot recover discarded mip variance; recook for role 3.

The first-moment interpretation follows [Toksvig's normal-map filtering paper](https://developer.download.nvidia.com/whitepapers/2006/Mipmapping_Normal_Maps.pdf).
Geometric lobe filtering follows the idea in [Tokuyoshi and Kaplanyan (2019)](https://www.jp.square-enix.com/tech/library/pdf/ImprovedGeometricSpecularAA.pdf).
The implementation here is an isotropic approximation, not their full
anisotropic projected-NDF algorithm. No third-party implementation was copied.

Geometric variance differentiates the normalized vertex shading normal over a
box pixel footprint. Raster uses quad derivatives and compute uses the hit
triangle's analytic ray differentials, never neighbouring illumination or
visibility. This is BRDF filtering, not screen-space lighting. Programs must
call texture/derivative helpers uniformly on raster paths. Programmable normal
deformation must supply corresponding derivatives or its own variance. This
does not implement the design's multi-triangle cluster-DAG S-AA2; a single
triangle cannot recover normal spread across unseen neighbouring triangles.

## Registered short screen

Generated, redistributable 512-square Gaussian slope normal map (sigma 0.035,
fixed seed); roughness 0.08/0.15/0.3 metallic patches, corresponding curved
vertex-normal patches, and a flat control. This extends S2's zero-shutter,
60 Hz camera/light measurement convention. It is a targeted rejection screen,
not the quarry, independent path-tracer cross-check or matched Unreal floor.

Quality: 320x180, 1x. Static plus 12 frames of 0.5 pixel/frame camera translation
and 12 moving directional-light frames. Reference: 256 independently scrambled
16x16 spatial strata per output frame, exact same camera eye and light, zero
shutter. Texture gradients are reduced by 16 for each subframe. No temporal
history, exposure changes, peak normalization or colour clipping in scoring.
The reference averages GPU HDR in one buffer, with one readback per output
frame. Raster reference is shared by both paths; its independence is limited
to sampling, not BRDF implementation.

Populations are each patch's two-pixel-inset interior and the full frame.
Register per-frame linear HDR RMS, signed/relative energy bias, display RMS,
peaks and temporal-difference residual RMS
`(c[t]-c[t-1])-(r[t]-r[t-1])`. Keep the candidate as default only if no static
or moving population worsens against the reference; record F3 bias separately.
Flat non-callers must remain unchanged. Full-frame PNG contact sheets are
inspected. Native 1920x1080 stage timings use eight repeats, distinct from
quality capture and reference cost. The software device requests no ray-query
features; the hardware device uses traced primaries. Costs are screening data
unless a final uncontended optimized run establishes a performance claim.

The aggregate improvement conceals a failure. The r=.08 normal-map patch's
camera flicker rises from .016030 to .025821 (non-RT), and .016030 to .025843
(RT). Light-motion flicker rises from .002532 to .029298 on both paths.
Full-frame maximum absolute energy bias also worsens: camera .16956 to .32672
(non-RT), .16949 to .32685 (RT). Static bias is .11504 to .31846 (non-RT),
.11455 to .31860 (RT). This fails F3 as well as the per-population error gate.

Inspection of the before/candidate/reference contact sheet confirms false
brightness in the dark, low-roughness mapped patch and excessive smoothing in
the mapped highlights. Inference: replacing a finite normal distribution with
one wider GGX lobe introduces heavy tails that do not match the sampled
distribution. Scalar first moments cannot describe its anisotropy or shape.
No view/light-dependent clamp or reduced quality threshold was introduced to
hide this failure. The design's stop rule applies: do not promote this filter.

The reference's interleaved 128-sample halves give full-frame RMS half-difference
divided by two of .12958-.30143 (.21868 static). This is a sampling diagnostic,
not a confidence bound on each population, nor an independent BRDF validation.
The small screen can reject the candidate; it cannot certify film quality.

## Reproduction

Outside any GPU lease, run the CPU checks above using a worker-owned target and
prepare `fixture.rla` with `cargo run -p renderlab-cook --example specular_fixture
-- E:/renderlab-work/m7-u1`. Invoke the compiled library test binary directly
under `scripts/m7-u1-run.py --label <unique> --minutes 3 --fast-check -- <binary>
renderer::specular_aa_tests::gpu_specular_aa_motion_screen --ignored --exact
--nocapture --test-threads=1`. The runner rejects Cargo as its command, uses the
shared lock and writes reservation/release lines. Check the shared schedule first.

Set `RENDERLAB_U1_ROOT=E:/renderlab-work/m7-u1`. First use
`RENDERLAB_U1_MODE=reference` without `RENDERLAB_TEST_PRIMARY`. Then use mode
`software` on that feature-disabled device, and mode `hardware` with
`RENDERLAB_TEST_PRIMARY=traced`. For timing-only 1080p runs set
`RENDERLAB_U1_NATIVE=1`, with distinct modes `software-native` and
`hardware-native`. Clear the native flag before quality/reference runs.
`py -3 -B scripts/m7-u1-score.py` regenerates scores and PNGs from the saved
buffers on the CPU. The matched UE/glossy-calibration dependency remains U0.
