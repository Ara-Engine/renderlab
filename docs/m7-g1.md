# M7-G1: world radiance cache, sky visibility

Unit G1 of [the M7 design](m7-design.md) (draft 2.2), branch `t3/m7-g1` on main `708e87c` (M7-U0 merged). Contract: [milestone-7.md](milestone-7.md). Claim constraints: [m7-p0-claims.md](m7-p0-claims.md) W1-W3, W8, C1-C5 and C8. Labels: **M** measured here, **A** author-reported elsewhere, **I** inference.

## Status

- **Built on both paths.** The world radiance cache (WRC) gives sky visibility through `indirect_irradiance`, with hardware rays on RT and software BVH4 rays on non-RT. The standard program uses it for sky diffuse. **It is off by default at this checkpoint** (`IndirectSettings::enabled`).
- **Quality on SV (M), default settings:** frame error **1.64% / 2.75%** (overview / gaps pose) against a path-traced sky-only reference, against 67.7% / 128.8% for the unoccluded sky.
  - The best variant reaches 1.23% / 2.03%.
  - RT and non-RT agree to two decimals in every row.
- **Gates that pass on both paths (M, final code):**
  - replays repeat bit for bit, in process and across processes;
  - a moving caster settles byte-identical to a fresh cache;
  - a sky step equals a fresh cache on the next frame;
  - serial and parallel tracing give identical tables;
  - a program that never calls the input runs no cache pass and draws the same bytes.
- **Cost (M, G1 quiet window `quiet-rotated`), default settings, camera moving, 1080p:**

  | Path | Frame cost | Of which cache passes | Of which shading lookup |
  |---|---:|---:|---:|
  | RT | **+0.684 ms** | 0.30 ms | 0.29 ms |
  | Non-RT | **+0.809 ms** | 0.46 ms | 0.28 ms |

  This passes the design's stop rules as defined (0.88 and 1.17 ms), and misses the stricter readings of L (section 4).
- **Memory:** 110 MiB, far under both Lumen totals.
- **Open:** no Unreal comparison yet (a sky-visibility-only Lumen capture is requested from U0b, section 6), no quarry gate, and no non-RT near field.

## 1. Design as built

**Code.**
- `src/gi_cache.rs`: state, settings, passes and profiling.
- `src/gi_bvh.rs`: non-RT geometry.
- `shaders/gi_cells.wgsl`: keys, records, lattice and SH.
- `shaders/gi_cache.wgsl`: the kernels.
- `shaders/gi_rays_hardware.wgsl` and `shaders/gi_rays_software.wgsl`: the two ray sources.
- `shaders/gi_api.wgsl`: the program input.

The cache pattern (claim/resolve inserts, epochs, queues) is copied from the N8o surface cache into these new files. No shadow file is shared or edited (M7 root decision).

**Cells.**
- A cell is a cube of edge `min_edge * 2^level` (`min_edge` 1/512 m) plus a six-way normal bin: the dominant axis of the receiver's geometric normal on its viewed side.
- The level is the smallest power-of-two edge at least `cell_pixels` (4) pixels of footprint at the receiver's distance.
- Lattice coordinates are `p / edge`. Along the bin's normal axis they are shifted a quarter cell against the bin, so a surface lying on a cell face sits well inside one layer whatever a module's rounding. The ground at y = 0 lies on a face at every level.
- The position is never projected (C2) and cells stay cubic (C3).
- Keys are two 32-bit hashes of (level, bin, cube). Key a (31 bits) picks an 8-slot bucket and is what shading compares, about 46 bits of name with the bucket index. Key b picks the start offset in the bucket.

**Records.** A slot is 160 bytes, in two arrays.
- **Hot record, 64 B, read by shading:** the key with a valid bit, an f32 scale, and the 27 L2 SH coefficients of the occluded sky (RGB) as f16 of that scale. A lookup's first bucket probe usually hits, so the key shares the record's first sector; a separate dense key array measured slower (section 4).
- **Cold record, 96 B, kernels only:**
  - state, last-seen frame, the cell definition, and the query point and normal;
  - one visibility bit per fixed direction (64 or 128), and a known-direction mask;
  - this frame's pending directions and first ray item (cleared by finish).
- **No field counts samples (W1, C8).**

**Fixed query point (W2).** A cell's rays start from a point fixed by its key alone:
- up to five probe rays run along the bin normal through the cube, from fixed points on its face, overhanging both faces by 1% of the edge;
- the first hit in fixed order is kept if its viewed side faces the bin, it lies in the cube, and a ray from it along its normal does not leave through the inside of a closed surface (a source-back hit);
- if none qualifies, the cell is an orphan and gets no lookup weight.

No pixel votes, and nothing is ranked.

**Values (W1).** A cell's fixed directions are a uniform Fibonacci hemisphere about the query normal, rotated about it by an angle the key fixes (the default; unrotated, cells with the same normal share their quadrature error). Tracing runs in three passes:
1. **Setup**, one thread per queued cell: the query point if the cell has none, then one 4-byte ray item per direction to trace, contiguous and in direction order.
2. **Rays**, one thread per item: the direction's visibility, as a bit at the item's index (`atomicOr`, so any order gives the same bits).
3. **Finish**, one thread per queued cell: the bits into its direction slots, then the SH as the fixed-weight quadrature `sum_k v_k L(d_k) 2pi/K Y(d_k)` over every slot in a fixed order. The SH *replaces* the stored value; there is no blend across updates.

Past the item capacity (2^20 per frame), setup traces a cell's rays itself. The rays and bits are the same either way, and `parallel_rays: false` forces that serial form for A/B tests.
- **Form 1** (`direction_phases = 1`, the default) traces every unknown direction at once.
- **Form 2** (`direction_phases = S`) re-traces the directions with `k mod S == frame mod S` and keeps the other slots. Untraced directions count as open sky until their phase comes round.
- An environment change re-integrates every cell from its stored bits, with no rays. Intensity is applied at lookup.

**Scheduling (W2), with no ranking.**
- Every new cell is traced in the frame it appears.
- A moved placement's swept bounds affect cells in two ways:
  - when the bounds meet a cell's cube, the cell re-probes and re-traces every direction;
  - when they meet some of its fixed rays (followed without bound), only those direction slots re-trace (the design's transport-record idea, applied to visibility bits).
- A fixed rotation (`rotation_period`, off by default) re-probes and re-traces cells with `(slot + frame) mod P == 0`.
- Frames whose camera, transforms, environment and settings repeat run no cache pass after three identical frames (idle frames).

**Inserts (C4).**
- The probe pass decodes each covered pixel's hit record into the receiver traced shading builds, and lists the cells the pixel reads. Each 8×8 tile deduplicates them in workgroup memory.
- Each unique cell is then looked up once: found cells are marked seen, and missing ones enter a frame-scoped request table that lists each cell once with the lowest requesting priority.
- Each miss picks the first free or evictable slot of its bucket and raises that slot's claim word with `atomicMax`. The highest claim writes the cell. Claim and resolve run three rounds per frame, dispatched indirectly from the miss count. The priority is a pixel index, which only breaks slot contention; it is not a characteristic of the cell.
- Cells unseen for `evict_frames` (120) become reusable. `reset_indirect` clears the table for cuts.

**Lookup (W3).** `indirect_irradiance(input, n)` reads the cells of the engine receiver (`input.receiver`), never a screen buffer.
- **Bilinear** (default) uses four cells in the bin's tangent plane, in the layer containing the point; **nearest** uses the containing cell.
- An optional **level blend** mixes the two levels around a level switch with a continuous weight.
- Every weight is fixed, and there is no jitter.
- Cells without a value get no weight. With no weight at a level it reads coarser levels, then the open environment.
- Each cell's SH is evaluated against the band-weighted basis of `n` on the spot (the clamped-cosine convolution), in lux, unexposed. No array is passed or returned by value.
- **Robust keys.** The kernels' f32 arithmetic can round differently from a shading module's. So within rounding of a deciding face, a level switch or a bin tie, the probe also requests the neighbour, and shading's own key always exists.

**Ray sources.**
- **RT:** hardware ray queries against the renderer's TLAS. Visibility rays are any-hit and unbounded; probe rays are closest-hit with vertex return. The cache's bind group is keyed on the TLAS generation *including this frame's pending build*, as `prepare_primary` keys its own; keyed on the encoded-build counter alone, the first frame of every transform change traced the previous TLAS.
- **Non-RT:** one software BVH4 traversal in R0c's record layout (20-word nodes with quantized byte planes, 8-word leaves), under a flat instance list rebuilt on the CPU when transforms change. Each ray is its own work item from the top, with no per-node hit lists or launches (W8).
  - `set_indirect_geometry` builds a full-detail BVH from a mesh's triangles. `gi_bvh::build` output passes R0c's own `Bvh::validate`.
  - `set_indirect_bvh` takes a cooked R0c sidecar at one level (built, not yet exercised on the quarry).
  - Moving casters are per-instance BLASes under their current transforms.

**Passes.** They run after the primaries' hit records and before shading, on traced (RT) and visibility-buffer (non-RT) frames whose programs call the input. Each indirect dispatch is sized by a one-thread arguments pass once its count is final:
1. probe;
2. miss arguments, then three claim/resolve rounds;
3. scan (event frames only);
4. arguments;
5. setup, then ray arguments;
6. rays, finish and integrate.

**Cost for non-callers.**
- `indirect_irradiance` is composed only into modules whose program names it (`program::uses_indirect`, a comment-aware token check), and frames whose programs never call it run no cache pass.
- Lighting group 3 gains binding 20, one read-only storage buffer. The cache kernels bind a header-only buffer there, so they never alias the table they write.

**Standard program.** Sky diffuse is `exposed_product(indirect_irradiance(input, n), base*(1-metal)/PI)`. Sky specular is unchanged and unoccluded: `indirect_radiance` is R1's in the design, so G1 does not add it.

**Defaults at this checkpoint.**
- `enabled` false;
- bilinear, 4 px cells, 64 rotated directions, no level blend;
- replace-on-update, parallel rays, 2^19 slots, no rotation refresh.

## 2. Method

**Bench.** U0's SV: scene.json `011ca96b…1e33d`, 1920×1080, 45° vertical field of view, poses `overview` and `gaps`, constant sky 4,000 cd/m², exposure −11 stops, all grey Lambert-plus-GGX (base 0.5, roughness 0.8).

**Reference.** `renderlab::reference` at `max_depth` 2 (camera, surface, sky: the sky term with visibility and no bounce), 2,048 samples per pixel, pixel-integrated. Its own relative noise is 0.38-0.51% RMS. References are cached on E: between leases.

**Gate program.** A user program, Lambert under `indirect_irradiance` and nothing else, so the image isolates the engine input. Its reference uses specular 0. The standard program's full image is scored separately against a specular-1 reference.

**Scores.**
- Per-pixel luminance error relative to the reference, floored at 5% of open-sky luminance, so near-black reference pixels cannot turn small absolute errors into huge relative ones.
- Edge pixels are excluded and scored as their own population: a 3×3 neighbour hits another placement or a triangle with another normal. The reference integrates each pixel's footprint while this frame samples its centre, so edges measure anti-aliasing (TR1's subject), not lighting.
- Populations are scene.json's lists, plus the ground within 0.3 m of each feature.
- **Crevice** pixels are those with a reference below 70% of open sky. An **over-occluded open** pixel has a reference of at least 95% of open sky and ours below 95% of the reference.
- **Motion** is the frame-to-frame change of that relative residual against per-frame references (bench-motion's `residual_change_rms`), over a 2 cm-per-frame pan of 9 frames at the gaps pose.
- Every final image and its ×8 difference against the reference was inspected, not just scored.

**Harness.** `renderer::gi_cache::gpu_tests::gpu_gi_sky_visibility_sv` (`src/gi_cache_tests.rs`), run through `scripts/m7-g1-run.py` under the shared lease (the `gpu-slot.lock` directory is held for every binary's whole run) and its guard.
- Each configuration is reset, then scored after five frames. The first and second frames are scored too.
- Timing sequences are continuous: no readback between frames, the renderer's own per-frame GPU spans, and the cache's per-pass timestamp ring read once at the end.
- A discarded warm-up sequence precedes the timed visits.
- `plan` runs a JSON list of steps (binaries, sections, gates) inside one lease. A failing gate stops the plan and releases the lease early.

**Why rotation is the default (M, inspected images).**
- Unrotated, cells with the same normal share one direction set, so their quadrature error is shared too. On flat faces that shows as **faint cell-sized rectangles** (about 1-3%), plain in the ×8 difference and just visible in the image.
- Rotated, the same error becomes a fixed fine mottle with no structure.
- 128 rotated directions with the blend are smoother still.
- Rotation adds no rays.

**Representation alone (CPU mirror, M).** With 64 fixed directions and L2 SH:
- the open plane is within 1.75% for shading normals up to 80° off the cell normal;
- it is within 6.4% beside a wall of any horizon.

All of that is quadrature error: 1,024 directions give 0.4%, and L2 truncation alone stays under 1% (`gi_cache::tests::representation_error_on_open_planes_and_walls`). That is why 128 directions and per-cell rotation help.

**Gates (M, final code, both paths).**
- **Determinism.** A reset sequence repeated in process gives the same table and image hashes. Two processes (runs `final` and `motion`) gave the same table hashes: `ff5b20856cad21ae` (non-RT) and `5993e592973cfb0b` (RT).
  - Serial tracing (`parallel_rays: false`) gives the identical table.
  - Table hashes skip the 64-word header, which holds the frame's settings.
- **Settle.** Every new cell is traced in the frame it appears. The first frame after a cut scores the same as the settled frame to two decimals.
- **Caster.** Ten frames of sphere motion, then the image against a fresh cache: **byte-identical** (0 pixels) on both paths. Two fixes made RT pass, from 250 differing pixels:

  - the reach test running from the rays' true origin.
- **Sky step.** Raising the sky by 1.5× gives a next frame equal to a settled fresh cache: 0 pixels differ, on both paths, in every run. Intensity is applied at lookup, so it lags 0 frames by construction. **Not tested:** a yawed prepared map (SV's sky is constant).
- **Non-caller.** Toon with the cache enabled runs no cache pass and draws byte-identical images.
- **Programmability.** A user Lambert program reads the input as the standard program does. The hit record is unchanged (16 B). G1 stores visibility only, so no program-derived value is cached.

- RTX 4070 SUPER 12 GB, NVIDIA 617.14, Vulkan, Ryzen 7 7800X3D.
- Development test profile, SV overview pose, 1080p.

**Where the rest of G1's frame cost goes** (RT camera, about 0.67 ms):
- the per-pixel probe, 0.19 ms;
- the shading lookup, 0.28 ms;
- tracing, about 0.08 ms;
- claims, clears and launches, about 0.12 ms.

- probe at the primary pass's decode instead of re-decoding hit records (this needs the primary's owner);
- one fewer claim round when no bucket conflicts;
- a cheaper key hash in the lookup.

## 6. Against Unreal

**Not scored.** The Unreal-floor gate for G1 is open on both paths.
- **What exists.** SV is imported in U0b's retained project (`/Game/M7U0b/SV/Bench`, `t3/m7-u0b`, unmerged), with SW and HW Epic content smokes. The brief is to use U0-family Unreal numbers once they are on main.
- **Why those smokes aren't a fair comparator.** Lumen's image includes sky bounce off the 0.5-albedo surfaces and Lumen's specular, while G1 is sky visibility for diffuse only (G2 adds bounce, R1 specular).

## 7. Constraints on user shaders

1. `indirect_irradiance(input, n)` describes the engine receiver only. Programs cannot query other points, by design (engine-computed input).
2. Its directional resolution is L2 SH per cell. A shading normal varies the result smoothly, but sub-cell directional detail (normal-map crevices finer than about 4 px) is approximate.
3. G1 is sky only. A program that also adds `ambient()` counts the sky twice.
4. Raster (non-traced) frames return the open environment; the cache runs on traced and visibility-buffer frames.
5. `indirect_irradiance` is a reserved name in program sources, and lighting group 3 binding 20 is reserved.
6. Values are lux including environment intensity, saturating at the f32 maximum. Products beyond f32 (M5's 1e30 × 1e20 range test) saturate rather than cancel; the standard program's affected term is zero in that test (metal 1).

## 8. Claim-avoidance notes (engineering reading, not clearance)

| Constraint | As built |
|---|---|
| **W1** (US 10,614,613 (f)-(g)) | No counter and no running mean. An update replaces the SH with a fixed-weight quadrature over the direction slots; form 2 keeps per-direction slots |
| **W2** (US 11,790,594 (a)-(b)) | Every new or event-reached cell is traced that frame. Rotation refresh is `(slot + frame) mod P`. The query point comes from the key alone. Nothing is ranked by age, distance or visibility. The claim priority (a pixel index) only breaks slot contention |
| **W3** (US 12,423,782 (a)) | Fixed bilinear or nearest weights, and the level blend's continuous weight. No jitter: the per-cell direction rotation is fixed by the key and does not move lookup taps |
| **C1** (US 11,315,310 (a)) | No reservoirs or resampling anywhere |
| **C2, C3** | Unprojected 3D positions; cubic cells |
| **C4** | `atomicMax` claims and winner writes, in rounds. The request table keeps the maximum priority with `atomicMax` |
| **C5** | Every pixel reads its cells. Fallback to coarser levels happens only where cells are absent, never by sample count or disocclusion |
| **W8** | Software rays are one-ray work items traversed from the top, with no per-node hit lists or launches |
| Per-direction caster invalidation | The design's transport-record idea, applied to visibility bits. Not flagged by P0 |
| Ray items | A per-frame allocation counter hands each queued cell a contiguous range of one-ray work items. It counts this frame's rays, not samples per cell (C8), and is cleared every frame; nothing is ranked (W2). Which cells get items past the capacity depends on thread order, but the rays and bits are the same either way |

No patented fallback is enabled.

## 9. Misses and open items

1. **No Unreal comparison** (section 6): the Unreal-floor gate is open on both paths.
2. **Cost against the stricter budget readings.** G1 passes the stop rules as defined but misses 0.3 × (Lumen over TSR) and the GI-pass readings by 1.3-1.8× (section 4). The probe and the lookup dominate and scale with pixels.
3. **Non-RT cut spike:** +4.8 ms with the default (4.4 ms unrotated) when every visible cell is new. Rays past the 2^20 item capacity trace serially in setup. More items (about 4 MiB per million) or a second item round would parallelize them.
4. **Cook-time near field (G-N1) is not built.** Non-RT traces exact full-detail software BLASes, which is exact on SV. The quarry needs R0c's LOD far field plus the near field, or the runtime near field (G-N1r). Lumen SW Epic's 5,142 MiB leaves room for a full-detail quarry BVH of about 350 MB (I).
5. **No quarry gate.** It waits for U0's quarry reference follow-up. `set_indirect_bvh` (R0c sidecars) is untested there.
6. **Residual mottle.** Rotated directions leave a fixed fine mottle on flat faces, visible on close inspection; 128 directions with the blend reduce it.
7. **Not tested:** a yawed prepared environment.
8. **Sky specular occlusion** waits for R1 (`indirect_radiance`).
9. **Leak at 8 px cells** in millimetre gaps: query points land on outer faces.
