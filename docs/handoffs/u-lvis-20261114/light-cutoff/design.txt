Smooth unshadowed-contribution cut-off: one-page design (paper only, 2026-11-14)

Goal and switch. Extend the existing engine bound with RENDERLAB_LIGHT_BOUND=smooth (unset remains OFF; black/sum keep their current meanings). Apply only to primary camera-receiver shadow tests for point/spot lights, on both paths. Reuse LIGHT_BOUND_CODES, initially 0.5 code per receiver, and the existing LIGHT_VIS_PASS bypass whenever LIGHT_BOUND is set. No new pass, per-pixel buffer, geometry record, temporal cache or light-count policy. Lamp exclusions remain parked.

Conservative input. The caller supplies c >= 0: this light's resolved, exposed RGB contribution at visibility 1, with the SAME normal, BRDF/specular-AA, material, attenuation, transmission and exposure the light loop actually uses. Because visibility V is in [0,1], removing any amount of its shadow changes each channel by at most c times that amount. This is a bound on the unshadowed endpoint, never the already-shadowed dark result, and never a Lambert proxy for a glossy BRDF. Thin/two-sided materials retain their own resolved response; no geometric-normal rejection. Nonfinite/invalid inputs trace exactly.

Use light_visibility_within, the existing opt-in seam adjacent to light_visibility. The standard program already supplies c. The corrected game fixture must opt into that same seam with its actual BRDF so its flight/night timings test this design. Enabled code computes the resolved response once and reuses it; disabled composition retains today's source/arithmetic. Plain light_visibility callers, including deliberate toon lighting, stay exact unless they explicitly provide a valid endpoint bound. Arbitrary programmable shading cannot be bounded from LightSample alone. Sun, GI-cell shading, reflection hits and transparent-pane shading are out of scope for the first change, preserving existing exclusions.

Bound and smooth window. Let L be a conservative per-view Lipschitz bound from exposed HDR RGB to the tested display transform, including known pre-curve white balance/linear grade gains. Start from the existing Filmic+sRGB global slope bound 6.443 (with its safety margin), not the smaller slope at black and not the order-dependent running-sum slope. Any additional active post transform must have a certified gain included in L; otherwise this mode fails open to exact shadow tests for that view. Do not claim a universal half-code guarantee through arbitrary contrast/LUT/bloom. Set E=LIGHT_BOUND_CODES and remaining R=E once per receiver in rl_lights_prepare; use a scalar B=255*L*max(c.r,c.g,c.b), conservatively inflated for float roundoff.

For each local light with R>0: if B<=R/2, return V'=1 WITHOUT a shadow test. Otherwise trace the original V and set w=smoothstep(R/2,R,B), V'=1-w*(1-V); when B>=R, w=1 and V'=V. Charge e=B*(1-w), then R=max(R-e,0). When R is zero, trace exactly. The total worst-case display error is <= sum(e) <= E: in the skipped region e=B<=R/2; in the transition B<=R so e<=R; beyond it e=0. All skipped and partially relaxed lights consume the SAME receiver budget. Strong lights do not consume it. Invalid inputs neither skip nor consume budget. The scalar remaining state and fade are continuous as c changes; at the ray-branch boundary w=0, so entering the traced branch adds zero shadow influence. This avoids a hard threshold shadow pop. Stochastic ray noise and ordinary material/light changes still require motion pictures.

Cost and test. No prepass/rescan and no resampling/reprojection. Added enabled cost is endpoint BRDF evaluation before the visibility query, the global-bound multiplication, smooth window, and one scalar accumulator; reuse the already-needed response to avoid duplicate BRDF work. Partial-window lights still trace, and SIMD divergence or cheap blocked rays can erase the expected saving. Ray counts diagnose only; they do not decide retention.

Gate. Focused Linux checks prove disabled module identity, cumulative bound, continuity at both window ends, fail-open values/unsupported post transforms, and the unchanged secondary/toon routes; compose and start both paths with the merged pass combinations. Ordinary pictures compare OFF/ON on corrected flight and night, held/moving plus a cut: per-frame differing pixels, >2/>8 codes, max and mean error, temporal difference, and OFF/ON crop pairs centered on the maximum-error pixel as well as the largest changed region; report each crop's max beside its mean and preserve all PNGs. Then one <=5-minute timing lease per feasible matrix: OFF/ON in two reversed rounds, both paths, warm held and moving, no frame readbacks. Report shading and full GPU span, actual build/scene identities, clocks and contention. Keep only a measured GPU-time improvement beyond the paired spread with an acceptable complete picture; a large saved-ray percentage is not success. If the conservative post-transform gate disables the experiment on a fixture, report that explicitly rather than timing a silently inactive mode.

Files/seams if retained: program.rs existing bound config/composition; program_api.wgsl existing visibility-within entry; standard.wgsl enabled response reuse; examples/game_scene.wgsl fixture opt-in; focused tests and docs/design-light-bound.md. Coordinate counter hooks through Root/U-MATWIRE. No visibility/U-RTVIS source edits, no implementation or lease yet.

No smooth code or build until this screen clears the paired spread. Smooth full-skip threshold with initially .5 remaining is .25/(255*6.443)=1.522e-4 exposed units; hard black initially permits .5/(255*6.443)=3.043e-4. Both share one receiver-wide budget and become stricter as it is spent. U-MATWIRE's own-rule count is diagnostic only. Add full-size crops of night's darkest shadowed regions, max next to mean and >2/>8 counts, looking for lifted blacks or moved band edges; audit light-list order under motion for steps.

Ceiling qualification: with the proposed continuous charge B*(1-w), hard and smooth can allocate their shared remaining budgets differently across later lights. Therefore the hard mode is an operational optimistic screen/kill rule, not a mathematical per-light ray-superset theorem unless reservation policy is aligned. No performance from saved-ray percentages is claimed, and an inconclusive hard screen still stops smooth implementation as ordered.
