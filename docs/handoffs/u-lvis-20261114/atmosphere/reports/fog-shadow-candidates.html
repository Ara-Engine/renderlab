No free clipmap on RT

The normal RT path has no maintained sun map; fog binds the TLAS. The non-RT Virtual buffers are explicitly excluded there. Root reports RT Outpost is 823 MiB lighter, largely because it lacks that clipmap. Enabling the full non-RT clipmap would add hundreds of MiB and page rendering to save about 1 ms: rule it out on memory. An explicitly selected Virtual mode elsewhere in the API does not make pages available in the measured RT configuration.

Query cost and the no-loss gate

FORCE_OPAQUE | TERMINATE_ON_FIRST_HIT and SHADOW_CASTER_MASK already apply. There is no unused opacity flag win. Fog's current tmax=100000m is independent of surface cascade reach; tighten it only with conservative caster bounds, not to fog distance (a distant caster can shadow nearby fog). Coherent 8 x 4 x 2 groups from the old branch retain all samples and are an exact-work control, but no current Ara speed win is measured.

Test Outpost, then Glint; Showcase has no fog. Compare today's RT rays against each retained default-off candidate: held haze/shafts, moving camera, moving sun/caster, a cut and the first frames after it. Use native-size crops where a caster edge crosses fog; inspect leaks, thin gaps, shifted bands, swimming and lag, with max/mean and>2/>8-code counts beside same-state controls. Any lag or unshadowed cut frame fails. Report map upkeep + injection, full atmosphere, frame span, and transient/per-view memory, including cuts. No option can honestly be called cheapest "with no visible loss" until that gate passes.
