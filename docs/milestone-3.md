## Unit B: materials and basic AA

The library now accepts prepared 48-byte vertices, immutable caller-owned textures/materials and explicit material draws. Materials retain shared texture ownership. Complete role-correct mip chains upload once through the bounded submission gate; creating another material does not upload its textures again. Materials occupy group 2, leaving camera and persistent instance bindings in groups 0/1. The viewer reads bounded prepared payloads directly and expands placements into primitive-major batches. It does not import GLB or decode images. Only the dependency-free asset crate was added to the runtime graph.

Base-color RGB textures are sRGB, factors and vertex colors are linear, and MR textures remain numeric (G roughness, B metallic). Diagnostic views show authored world normals and MR values. Materials are opaque and unlit. The default material retains colored geometry's double-sided behavior; prepared single-sided materials reject source backfaces in the fragment shader, correcting determinant sign for mirrored instances without changing slot order. This incurs fragment work that hardware backface culling could avoid.

Normal matrices use an f64 inverse transpose, rescaled before f32 storage. Normal diagnostics and single-sided materials require nonsingular affine transforms with max-element(A) × max-element(inverse(A)) <= 10,000. This is an explicit conservative supported domain, not a universal error bound. Raw double-sided unlit rendering still accepts general finite model matrices. Each slot adds 64 CPU bytes and 64 GPU bytes for normal data; changed transforms upload 64 model bytes and 64 normal bytes. Immutable frames do no normal recomputation. No large-scene M2-to-M3 normal-cost attribution is claimed.

`RendererOptions.samples` fixes one or four samples for the renderer lifetime. The caller output is single-sample; matching internal color/depth attachments resolve into it. Resize replaces attachments under the existing flight policy. Reload compiles a candidate for the active sample configuration and retains the complete old pipeline on rejection. Exact depth-oracle checks use one sample; MSAA checks inspect resolved color.

Root corrected the viewer's camera error propagation for large translations that collapse eye/target precision, clarified scene/setup log labels, and bounded upload scheduling to two milliseconds between operations per wake, stopping on Busy. An individual upload may exceed that scheduling budget. The upload-wall counter now starts at the first upload attempt; earlier `wall_ms` included window/device initialization and must not be interpreted as upload duration. A first timing comparison therefore did not establish an upload-speed improvement. The viewer avoids redundant title publication, and Unculled camera-only changes avoid slot retests.

## Independent acceptance and sampler correction

Opus reviewed `f29f1f2`, independently recomputed source identity, all optimized table cells, development medians, replacement overlap and image evidence, and found one blocking defect. A disabled-mip sampler clamped maximum LOD to zero, which selects the magnification filter even when the texture is shrinking. The corrected maximum is 0.25 with nearest mip selection: positive LOD permits the minification filter while still choosing the base level. This follows the [Vulkan sampler specification's filter-mode mapping](https://docs.vulkan.org/refpages/latest/refpages/source/VkSamplerCreateInfo.html).

Root first added a GPU case with a nonuniform 2x2 base texture, strong minification and opposite min/mag filters. Before the fix it failed with gray `[188,188,188]` where nearest required an original base texel; the failed run remains at `measurements/m3-review-fix/red`. After the fix, nearest/linear and linear/nearest both pass, while existing disabled-mip assertions still select level zero. Root inspected both new full-frame captures.

Final corrective verification is `measurements/m3-implementation/check-20261103-015532`: fmt, locked workspace/all-target check, Clippy, 21 CPU and ten GPU tests pass; GPU process time 37.470 s, ten validation summaries with zero errors/missing layers and 36 positive activations. Before/after identity now includes `.cargo/config.toml` and `scripts/measure-dev-loop.ps1`. The earlier 34-file identity and all performance/window evidence predate this fix. Neither prepared fixture uses disabled mipmaps, so their results remain applicable; they were not relabeled as reruns.

The review's wording corrections distinguish Frustum/Unculled equality at each sample count from equality between sample counts, and identify restored Rust source timestamps as the first isolation rebuild's cause.
