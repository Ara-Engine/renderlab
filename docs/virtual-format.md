# Virtual prepared boundary, version 1

Unit A supplies CPU preparation and selection; Unit B integrates it with the [bounded runtime](virtual-runtime.md). M4 acceptance remains pending. `renderlab_asset::virtual_mesh` has no dependencies, GPU types or importer. M3 RLA1 is unchanged and remains the full-detail image reference. A virtual package never embeds source geometry in its resources.

`Package` owns `VirtualMesh` records, global `Page` records, placements, and an M3 `Asset` containing only shared materials/textures. Each mesh owns topologically ordered replacement `Group` records and contiguous `Cluster` records. Newtypes distinguish GroupId, ClusterId and PageId. Groups store upstream accumulated simplified sphere/error and depth. A group's clusters are the fine representation; incoming clusters whose `refined` names it are all shards of its coarse representation. `None` marks original geometry. Terminal groups are identified by error exactly finite f32::MAX, including shallow stuck groups. The optional upstream spatial forest is not stored or confused with replacement ancestry.

A cluster records owner, optional refined group, culling sphere/error, material, global page ID and a u32 index-array span. Cluster bounds do not supply monotone selection error. A page stores vertices, indices, actual payload length and SHA-256 of its entire zero-padded 65,536-byte file. Layout is 48-byte M3 vertices, then u32 indices addressing that page's vertex array, then zero padding. Several clusters draw ranges of the same page buffers. Page padding is disk/logical page storage, separately reported from payload. Buffer alignment, staging and retirement charges belong to runtime integration.

## Binary metadata

All integers are little-endian u32 except the noted u64. Floats preserve IEEE f32 bits. No native padding or compression exists.

| Record | Fields in order |
| --- | --- |
| Package header | `RLV\0`, version 1, mesh count, placement count, page count, resource byte count |
| Resources | Exact RLA1 resource bytes; mesh/placement counts must be zero |
| Mesh | Group count, cluster count, all groups, all clusters |
| Group (32 bytes) | Depth, simplified bounds (center XYZ/radius/error), cluster offset/count |
| Cluster (44 bytes) | Owner, refined (`0xffffffff` = original), bounds, material, page, index offset/count |
| Placement (68 bytes) | Mesh, column-major 16-float affine transform |
| Page (44 bytes) | Vertex count, index count, payload length, digest[32] |
| Current/key manifest (80 bytes) | `RVM\0`, version 1, key[32], package digest[32], package file length u64 |

Cache locations are `virtual-v1/{keys,packages,pages}/<sha256>`. No manifest-controlled arbitrary paths exist. The metadata's materials/textures use the original role/sampler/mip codec. Page files can be read independently after metadata admission. `decode_page(page, bytes, actual_sha256)` requires the caller to calculate SHA-256 of the actual entire file. The dependency-free asset crate compares that digest, validates exact size/zero padding, finite vertices, normals, colors and local indices. It does not implement cryptography. The cooker uses pinned sha2; Unit B must wire hashing before availability publication.

Decode caps counts and charges metadata/container storage before allocation, checks resource decode limits independently, then validates aggregate metadata plus validation scratch. Defaults are 65,536 groups, 131,072 clusters, 8,192 pages, 8 MiB metadata/validation scratch and 512 MiB disk page geometry. Unchanged M3 resource/input limits still apply. Checks reject truncation, trailing bytes, nonfinite/negative spheres/errors, cyclic/unordered/depth-inconsistent links, nonmonotone group errors/bounds, wrong terminal markers, unowned clusters, bad materials/pages/placements, overflowing/out-of-range/overlapping/uncovered page index spans and inconsistent payload counts. Counts report element storage, not allocator capacity or process RSS. Texture decoding retains M3's separate allocation allowance; the runtime's 64 MiB texture policy is a later admission gate.

## Pure cuts and demand

`select(mesh, projected_errors, threshold, published_pages, SelectionBudget)` rebuilds a per-mesh, per-instance cut from every terminal group. Scalars must be nonnegative and monotone from refined groups to owners; positive infinity is permitted, NaN/negative infinity are rejected. Every terminal error must exceed the finite nonnegative threshold. Projection belongs to runtime: a tested example uses error / max(distance - radius, positive near) times half the viewport height and cot(fov/2), followed by a topological maximum over incoming errors. Unit A tests positive uniform scale, very near and inside-sphere cases. This approximation does not guarantee one-pixel image error. Unit B must declare and verify supported affine scale/near/normal/winding behavior independently.

An active group replaces all incoming coarse shards. To refine a group, selection propagates activation through every owner, computes the final cut, and checks output/page capacity before publication. A transaction needs only its final-cover pages and pinned root pages. Intermediate pages removed by that same atomic transition are neither required nor requested. The logical geometry capacity conservatively charges current cut pages plus the proposed final cover plus pinned fallback. Runtime will additionally charge staging/retired allocations and other instances/assets; this local scalar budget is not a complete GPU admission algorithm.

`Selection` returns `Cut` (active groups, cluster IDs, selected page IDs), `Demand` (required final-cover/root pages and their unavailable subset), `QualityDebt` (unresolved groups, maximum denied projected error and reasons), plus work counters. Candidates use descending projected error, then descending group depth, then ascending group ID. The depth tie-break shares coarse refinement across regions before fine geometry consumes capacity, including when near-plane errors tie at infinity. Each attempted closure consumes a candidate, including denied and unavailable proposals.

Selection keeps owner-closed, terminal-including planned P and published U sets, with U a subset of P. A seed missing from U costs one candidate, including denials, even when it is already in P. If absent from P, its owner closure first proposes a new plan under output and `target(P') | cut(U) | pinned | protected` page limits; denial rolls back and skips publication for that seed. If the whole admitted plan is available, publish it. Otherwise independently propose `closure(U, seed)`, publishing only when its complete cut is available and both its output and `target(P) | cut(U') | pinned | protected` fit. Thus a missing page in one region cannot by itself block a resident refinement elsewhere. A larger published cut can constrain subsequent planning; capacity-bound outputs intentionally differ from the historical complete-plan-only policy. No resident fallback is discarded or pool overbooked to force progress.

The publication step never creates IO demand. Returned demand describes only the final feasible plan (plus pinned pages), requested pages are exactly its unavailable subset, and debt describes the published cut. Later plans can eliminate missing intermediate representations without requesting them. Candidate, output and page exhaustion preserve complete coverage. A pool or output cap below the terminal minimum, or unavailable root pages, rejects admission. `select_with_protected` charges a package-global protected page union. `select_from_cut` admits a canonical legal published cut: all terminal groups, owner closure, exact IDs/ranges/pages, resident cut pages, and admitted output/geometry. Unlimited selection retains the upstream group-error rule. Runtime unions scene protection, reserves staging, and charges retirement. Assets have explicit independent pools; applications budget their sum.

`PreparedPackage::new(package, limits)` applies `Package::validate` once and retains one incoming-link index per mesh: `(n+1)` usize offsets plus one u32 per refined cluster, ascending by cluster ID. Before allocating, it charges those bytes, the outer index vector and one transient n-usize build cursor together with the package's element metadata against `max_metadata_bytes`; validation scratch is already released. Exceeding it returns `prepared selection index budget`. The package is owned by value and exposed only through `Deref<Target = Package>`: there is no mutable access, so neither metadata nor index can change after preparation. `PreparedPackage::mesh(i)` returns a Copy `PreparedMesh` view. Its `select(errors, threshold, available, budget, protected, initial)` has the policy, outputs and errors of `select_with_protected` (no initial cut) or `select_from_cut`, skipping only structural mesh validation and the per-call index. Every call still checks the protected range, the unchanged scratch admission, the scalar error domain, terminal threshold, monotone errors and initial-cut admission, and requires exactly one `available` entry per package page. The checked functions keep validating arbitrary caller metadata on every call.

The checked selector constructs a per-call CSR index of incoming cluster links; a prepared view borrows its retained index instead. Planned and published covers each own group flags, page reference counts, and cluster/missing counts. Fixed bits and one shared union count charge page overlap once. Either track uses the same bounded owner-closure and inverse page-delta journal; denial restores that track and the shared charge without re-reading clusters. Accepted plan additions enter an at-most-n gap list. Whole-plan publication filters already independently published groups from that list, then applies the remaining boundary as one batch. No per-candidate whole-cut reconstruction or page-vector construction is used. The prepared incoming index is the only retained per-asset selection state; there is no cross-frame selection cache.

Scratch admission is `32 * groups + 48 * clusters + 16 * page_count + 8` bytes. It is checked before selector allocation, including page-indexed state for unused package pages. On 64-bit hosts, steady scratch uses two group bitsets, `(n+1)` usize CSR offsets, at most c u32 links, n u32 ordering entries, two at-most-n u32 journals, and one n proposal bitset. An at-most-c `(PageId, bool)` delta journal takes 8c bytes. Page state is two P u32 reference counts plus P fixed bits. A checked call's CSR construction drops its n usize cursors before the covers/journals are created. Prepared calls admit against the same formula, although they allocate no per-call CSR offsets or links; the retained index is charged at package preparation instead. Group output has an explicit n capacity. Cut, pinned, demand and requested scratch vectors have capacities bounded by c; returned cluster/demand/requested vectors discard excess capacity before being retained by a scene, so whole-mesh scratch does not multiply per placement; there is no per-candidate page-vector construction. Initial admission's union bitset is P bytes and drops before incremental state. Even duplicate protected IDs never allocate from the length of that caller slice. The remaining envelope covers validation, old/new cut vectors and small reason storage. The bound excludes caller metadata/errors/availability, allocator headers, stack and proof-harness allocations. Runtime separately reserves this page-count term under its unchanged 8 MiB metadata-plus-scratch cap.

`cluster_visits` counts actual cluster predicate, incoming-link and shard touches in cut/CSR construction and proposal/rollback/publication work. Boundary validation, scalar-error checks, group/page scans and sorting are excluded. A prepared call performs no CSR passes, so it reports exactly `2 * clusters` fewer touches than a checked call on the same input. The preserved oracle's original `c + 2*c*candidates` counter counts only whole cut/closure scans. It omits page extraction and initial/final work. Report counters with those definitions. C1a old/new ratios apply only to its proven identical policy. C1b counts both tracks; differing policies and IO histories do not supply an equivalent-work ratio, and cluster touches do not measure all CPU operations.

The non-default `renderlab-asset/selection-oracle` feature exposes `selection_oracle`, preserving the original complete-plan-only scan implementation as a historical baseline. C1a's identical-policy evidence remains valid for that checkpoint; current two-track output is not asserted equal to it. Normal binaries do not compile it. Root `selection-shadow` now asserts cut/demand/debt/candidate equality against the independent ordered-set two-track policy on every actual runtime selection call, including retained-cut calls. Exhaustive and seeded asset tests use the same independent policy source. Shadow runs are expensive correctness evidence and must never supply timing claims. Work counts from different policies cannot establish an equivalent-work speedup.
