## Throughput and ownership

- Blocking first step: establish the typed prepared representation, supported GLB subset and deterministic fixtures before renderer changes.
- Independent workstreams: none for the first unit; the format, cooker and fixtures must agree on one representation. Read-only review may run separately.
- Shared state: one source owner per unit; root owns milestone/design documents and acceptance. GPU runs, builds and source-mutating development measurements remain serial.
- Smallest safe decomposition: unit A creates prepared data and cooking with CPU/CLI evidence. Root validates and pushes it. Unit B integrates owned textures/materials and the viewer, strengthens M2 fixtures, adds basic AA and collects GPU/interaction/development evidence. Only then close M3 and start M4.

## Unit A: typed prepared data and isolated cooking

Add a small `renderlab-asset` crate with no wgpu, winit, glTF parser or image codec, and a separate `renderlab-cook` CLI/library. The runtime will depend only on the prepared crate. Keep importer and codec features out of ordinary `cargo build -p renderlab-viewer`; workspace-wide checks intentionally include them. Pin the selected gltf 1.4.1 and image 0.25.10 with defaults disabled, enabling only needed accessor utilities and PNG/JPEG. Use a small pure-Rust content hash dependency deliberately; record its license and build effect.

The owned domain model is `Asset { meshes, placements, materials, textures }`. A mesh contains ordered primitives; each primitive owns vertices/indices and a material index. A placement references a mesh and stores the composed source hierarchy transform. Repeated nodes share geometry. Vertices carry position, normal, UV0 and linear RGBA color. Materials carry linear base-color factor, metallic/roughness factors, optional base-color and MR texture references, sampler interpretation and double-sidedness. Textures carry their color/data role and complete prepared RGBA8 mip chains. Shared image data used in both roles gets separate role-correct prepared records. All indexes and dimensions are validated before use.

Use a versioned, deterministic binary envelope and explicit bounded decoding. Counts and byte ranges must be checked before allocation or slicing; reject truncation, nonfinite data, invalid indices, inconsistent attribute counts and invalid mip sizes. Identity includes complete embedded source bytes, schema, cooker algorithm version and settings. Verify cached payload content rather than trusting the filename. Immutable content-addressed entries plus an atomically published complete manifest prevent partial results becoming cache hits. Corrupt/missing entries recook or return a precise error. Transform edits may recook metadata but preserve equal geometry payload hashes. Cold cook, cache lookup/load and publication have separately reported time/byte counters.

Initial supported input is GLB 2.0 with embedded buffers and PNG/JPEG images, static triangle primitives (indexed or nonindexed), UV0, colors, normals, node hierarchy/repeated meshes, opaque metallic-roughness material data and samplers. The cooker renders nothing. Preserve supplied normals; missing normals may generate explicitly documented flat normals, expanding vertices as needed. Textured primitives require UV0. Restrict imported node transforms to finite nonsingular affine matrices; M2's general finite transform support remains intact for raw rendering.

Reject external image/buffer URIs, skins, animations, morph targets, unsupported primitive topology, extensions, nonzero texture-coordinate sets, unsupported texture roles and alpha modes with named diagnostics. Do not silently discard visual features. Metadata such as names/extras may be ignored if documented. No normal-map/tangent path, lighting, transparency or material graph is implied. Encode concrete file/count/decoded-byte limits, including node traversal and allocation limits; do not rely solely on glTF validation. Handle source buffer offsets/strides and normalized supported attributes or reject them explicitly before reading.

Base-color RGB is sRGB in texture storage and linear in material/vertex factors; MR channels remain linear (G roughness, B metallic). Build color mips in linear light and data mips numerically, including odd dimensions and the complete final 1x1 level. Preserve wrap and min/mag/mipmap sampling choices. Test swatch values independently of the cooker implementation.

Generate two self-authored GLB fixtures with a reproducible generator and provenance: a textured multi-material mesh reused under parent/child, mirrored and nonuniform transforms; and a distinct textured curved/thin-feature object with odd-sized images and different samplers. Fixture bytes must be deterministic. Generated bulk outputs stay ignored; commit small source fixtures only when useful with their generator/provenance. No third-party art or Ara source. Preserve adopted dependency notices and record versions without assigning Renderlab a project license.

Unit A acceptance: focused format/cooker tests, malformed/truncated/missing-resource/unsupported-feature cases, deterministic two-asset CLI cooking, warm reuse, corruption repair/rejection, settings/source invalidation and atomic publication behavior. Record source/output hashes, actual counts and cold/warm times. Demonstrate with Cargo dependency trees/checks that runtime edits do not include importer/image dependencies. No GPU evidence is claimed at this checkpoint.

## Unit B: material rendering and inspected quality

Integrate prepared vertex data, caller-owned texture/material resources and group-2 material binding into the existing renderer. Keep immutable mesh/material publication, immediate bounded uploads, renderer affinity, transactional shader reload and resource lifetime accounting. Reuse geometry and textures across placements/materials; primitive-major batches preserve explicit draw order. The viewer loads prepared assets without invoking the importer. Report decoding/upload time and texture bytes separately from geometry and instance bytes.

Render unlit base color faithfully. Normal, metallic and roughness diagnostic views verify stored values without pretending physical lighting exists. Normal handling must be correct under supported nonuniform/mirrored affine transforms. Undefined normal transforms need an explicit diagnostic/restriction; a cofactor shortcut is not proof for arbitrary projective/singular inputs. Preserve the raw M2 API's finite-transform contract. Single-sided and double-sided materials need mirrored-winding tests.

Measure a deliberate basic-AA path, initially one versus four samples if supported. The caller's output texture stays single-sample; internal multisample color/depth attachments resolve into it and follow the existing bounded in-flight replacement policy. Avoid an unnecessary pipeline rebuild each frame; rejected reload must preserve the complete active pipeline configuration. Retain one-sample exact-depth/oracle tests and add color/edge quality plus motion evidence for AA. Compare accepted quality and GPU/memory costs on the same content/camera; no temporal reconstruction claim.

Fold M2 review recommendations into this unit: isolate eye/near-plane geometry from narrow/portrait grid checks, add mirrored-color equal-depth ties within one collection, cache unchanged window titles, and avoid retesting Unculled slots solely because the camera changed. Preserve meaningful test gates and measured baseline identities. Optional confirmation of the closed M2 commit should preserve its executable before M3 rebuilds.

M3 acceptance includes actual images for both assets and diagnostic modes; material boundaries, silhouettes, normals, mirrored sidedness, UV/sampler/mips and color-space assertions; camera/object motion, resize/minimize, invalid shader and recovery; replacement stress and positive validation with no unexpected errors. Recheck prepared cache behavior and development latency after integration. Measure fresh/runtime/cooker edits separately, with hardware/build/contention labels. Root inspects complete frames and interactions and obtains focused independent acceptance review before closing. M4 remains unimplemented until that gate passes.
