# Virtual geometry runtime

Unit B implements bounded page IO and hardware rendering; M4 and Unit C acceptance remain open. No Unreal or Nanite performance/quality claim follows from this API.

## Ownership and entry points

`virtual_geometry::VirtualAsset::open(cache, manifest, StreamOptions)` performs a bounded synchronous metadata bootstrap. It validates the 80-byte RVM1 manifest, reads only its SHA-addressed package, hashes the actual package bytes, and validates metadata/resources. It never scans or preloads the page directory. A 24-byte header preflight charges encoded metadata together with decoded metadata/validation scratch against 8 MiB before allocating the body; a conservative 1 MiB reservation covers M3 resource containers. Encoded resources and decoded resource storage each have a 64 MiB bootstrap bound, so setup can temporarily hold up to 128 MiB of resource bytes while decoding; retained source mip capacities then have their 64 MiB bound. These setup allocations are separate from the four-slot streaming payload bound and from GPU texture memory. `VirtualAsset::new(package, page_directory, options)` validates it once into an owned `PreparedPackage` (metadata plus each mesh's incoming-link index) and admit-checks it; `open` decodes, which also validates, before calling `new`. `asset.package()` returns that prepared package, which dereferences to `Package` read-only. Runtime selection goes through its `PreparedMesh` views, so frames do not repeat structural validation or index construction; per-view checks remain. The normal runtime dependency graph adds only sha2; the dependency-free asset crate still supplies the owned codec and legal selector. The cooker/importers/codecs remain outside runtime/viewer dependency edges.

The asset owns package metadata, materials/textures, page states, worker and geometry pool. `VirtualScene::from_package(&asset)` uses recorded placements; `VirtualScene::new(&asset, &[VirtualPlacement { mesh, transform }])` admits other placements. A scene owns one persistent M3 `Instances` collection, mesh IDs, legal per-placement cuts and a metadata/output reservation. `scene.set(slot, model)` validates before mutation. Multiple scenes can share an asset. Their selected/demanded pages are unioned, pages are charged once, and aggregate output, candidates and metadata reservations apply across registered scenes. Drops release scene reservations; unprotected geometry is reclaimed under subsequent pressure. Scheduling uses caller scene and placement order. Candidates use descending projected error, descending group depth, then ascending group ID. Page reads and uploads use increasing page IDs. Fairness between continuously changing independent scenes is not promised. Different assets are explicit independent pools: callers must sum their configured caps. There is no process-global asset registry or implicit global memory cap.

`renderer.try_render_virtual(color, camera, &mut asset, &mut scene, view_mode)` progresses IO/uploads nonblockingly, then borrows page ranges for the same pass as `try_render_view`. `None` means startup/backpressure: retain the prior presented image. Minimum pages also come through the worker. Initial missing/corrupt roots cannot produce an image; a failure after usable roots preserves a legal cover. `asset.advance(renderer, scene, camera, height)` is available for non-rendering wakes; one call is one streaming tick and admits at most two page uploads. Do not call it separately and also render in the same intended tick if the two-upload policy is required per application frame. No ordinary frame waits for IO or queue completion.

Geometry is uploaded once per resident episode: one vertex buffer, one index buffer and one explicit staging buffer per page. Every cluster selects an index-array span, with a per-placement range of the scene's shared instance-ID buffer. There are no cluster geometry copies, cluster instance buffers or retained full-original mesh fallback. M1 raw `Draw`, M3 prepared assets, `CLEAR_COLOR`, shader `TINT`, material/normal/winding behavior, MSAA and transactional reload remain available. Virtual draws are conservatively unculled; offscreen placements still consume their legal minimum/output admission.

## First-view preparation and progressive presentation

`scene.ready(&asset)` means a complete legal cover can be drawn immediately, even while detail loads. Library callers keep this progressive behavior with `try_render_virtual`, including after camera cuts and under failed IO or constrained budgets.

For a prepared first image, call `asset.prepare_view(renderer, scene, camera, height)` once per event-loop wake. It performs exactly one ordinary bounded `advance` and returns `ViewPreparation`; `scene.preparation(asset, camera, height)` observes the same status without advancing. Status comes from the existing selection key, owed continuation, admitted cover/demand and authoritative page states. It adds no queue or resident geometry. Camera view/FOV/near, viewport height, transform, availability and registry changes invalidate settlement through that key. Width alone does not change vertical pixel error; rendering still uses both target dimensions. Debt fields describe the last selection, which may be stale while pending.

| State | Meaning and caller action |
| --- | --- |
| `Pending` | Resources, current-view selection/continuation or admitted page work remains. Service events, shader polling and renderer polling. `cover_ready` separately exposes a usable progressive preview. |
| `Settled` | Actionable work settled with no reported projected debt. This is geometric preparation, not an image-quality certificate. |
| `Degraded` | Actionable work settled with debt or demanded failed pages. A legal fallback is available. Label its limits using `failed_pages`, `candidate_limited`, `output_limited`, `geometry_limited`, `unresolved_groups` and `asset.failure(page)`. Capacity denial does not wait for zero debt or guarantee full image quality. |
| `Failed(PageId)` | A pinned root failed: no complete cover is available. Surface the error. Repair the file and explicitly `retry(page)` to resume. |

Failed detail is terminal after other actionable demand settles; it never retries automatically. Unrelated reads are not directly awaited, but shared asset/registry revisions can return preparation to pending while another scene changes its cut or forces evictions. Callers with several live scenes on one asset need their own deadline or progressive fallback. An unchanged settled/degraded view stays quiet once shared revisions stop changing. Explicit retry or changed view/transform/height can return it to pending. The runtime introduces no time-based preparation policy; cancellation/deadlines belong to callers. OS file latency has no scheduling guarantee.

After settlement, `renderer.try_render_prepared_virtual(...)` draws the same view without advancing a second time, preserving the upload-per-tick bound. It returns `None` for stale/pending preparation or submission backpressure, and an error for failed roots. Check status to distinguish degraded output. After first presentation, use ordinary `try_render_virtual` for streaming and immediate covered fallback; do not gate later camera cuts behind preparation.

Viewer and replay default to first-view preparation. The viewer prepares before surface acquisition; wakes retain input/camera updates, shader polling and renderer polling. Minimized/occluded redraws defer preparation until drawable. Its title reports preparation or initial degradation; failed roots exit with diagnostics. Registered pose 0 stays fixed until first presentation, then the original trajectory advances by presented images. The offscreen replay uses exactly the same preparation and prepared-draw APIs, holding its requested start pose before frame 0. `--progressive` explicitly opts into coarse startup in either tool. The viewer path is not yet interactively verified.

No correction evidence uses `--warmup`. Replay's existing 120-second frame/admission deadline also bounds preparation; this is a tooling deadline, not a new runtime resource ceiling or quality heuristic. `startup.csv` records main-entry-to-device/renderer setup, metadata setup, first legal cover and first scene submission, with ticks/reads/uploads/submissions. Main entry is a process-start proxy and includes safety guards, validation, file/bootstrap and tooling overhead. Offscreen submission is not presentation/scanout. `preparation-ticks.csv` records each advance wall/poll duration, status and renderer flights/submissions. `preparation.csv` retains complete cumulative stream work and resource observations at each tick. `frames.csv` cumulative work starts at the preparation boundary, avoiding a giant loading delta in frame 0; gauges/peaks retain whole-run meaning. Progressive mode separates unsuccessful admission attempts from the successful frame-0 attempt. Explicit warmup work is retained in `warmup.csv` as per-tick deltas and excluded from normal-frame cumulative work. Sum work across these boundaries, but take maxima of resource gauges. Final summaries retain whole-run stream/renderer totals. Capture/readback waits remain explicit correctness costs, unsuitable for normal timing claims.

`scripts/m4-startup-check.ps1` provides guarded, finite `build`, `run`, `focused`, `checks` and `restore` operations with binary/source records and fresh output names. Build with `-Phase build -Name candidate-dev`, then run `-Phase run -Name images-sheet --manifest measurements/m4-cook/root-unit-a/material-thin.manifest --frames 631 --capture 0,210,270,630 --frame-period-ms 16.67`. `-Phase checks -Name runtime-check` includes all 18 GPU cases and affected all-feature CPU/Clippy checks. It does not automatically accept M4.

## State, IO and completion

Pages have one enum state: missing -> queued -> ready -> uploading -> resident -> retiring -> missing, or queued -> failed. Failed pages retain one fixed 256-byte UTF-8 diagnostic slot and never retry automatically. `failure(PageId)` reads it; after repairing the file, `retry(PageId)` explicitly resets that failed page. Root failure on startup is observable through these same APIs. No error/event history grows without bound.

One worker has at most four outstanding requests, counting active reads, bounded completion-channel payloads and main-thread ready payloads together. It reads at most 65,537 bytes from each page path; exact 65,536-byte extent, real SHA-256, zero padding, attributes and page-local indices pass `decode_page` before publication. The extra byte detects trailing data. Ready data is decoded vertices/indices, not an entire full-detail source. Four retained payloads plus one worker raw/decode overlap have a 327,681-byte element-allocation envelope. Requests/worker bookkeeping are separate small metadata overhead. `cpu_ready_bytes` is main-thread ready-vector capacity; queued completions remain covered by `cpu_io_bound_bytes`, not directly sampled in that field. Delay injection waits on the worker after the actual read/hash/decode and before result delivery. Dropping the worker disconnects completion sends and request receive before join and unparks an injected delay. OS filesystem latency remains outside the application's scheduling control.

The existing three-flight gate remains authoritative, with upload admission below two occupied flights. Renderer submissions have monotonic IDs; `completed_submission()` is a completion watermark independent of the bounded observation queue. An upload records its submission/last use. Published draws update each used page's last use. Staging remains charged until upload completion, and retiring vertex/index buffers remain owned/charged until their last submission completes. A later queue completion proves earlier queue work complete; a dropped caller handle or discarded telemetry event proves nothing. Rendering/reload share the existing timestamp/clear/depth/material/MSAA path. Only explicit evidence capture/final test drains wait for a result.

Upload admission reclaims pages in ascending page-ID order, skipping the sorted union of pinned, selected and demanded pages. Each make-room call snapshots its incoming charge once and keeps geometry and retiring bytes local to that call. Under pressure it performs one completion scan at the first unprotected loop iteration, after that iteration's eviction, preserving the existing completion/publication point. At the same fixed watermark, later completed resident evictions release their own allocation directly; incomplete last-use allocations stay retiring and charged. No persistent accounting cache is added. The original scan policy is retained only in a focused GPU test that compares final states, revisions, exact charges and peaks, including protected pages, uploading staging, completed/incomplete retirement and insufficient space. The separate real in-flight eviction test still requires observed unfinished draws.

Make-room takes at most three full snapshots, independently of the number of evictions. Its local retiring total observes each transient retirement in `retiring_peak` before immediate release, including already-completed last use. Entry and exit snapshots retain exact owned, staging, pinned and retiring observations; uploads retain their existing post-allocation snapshot. Snapshot geometry charge comes from the same pass's GPU-state counts and actual staging bytes, avoiding a second state scan. Completion publication timing and the deterministic eviction policy are unchanged; asynchronous wall-clock IO/GPU interleaving can still differ between executions.

## Budgets and transform domain

A resident or retiring page reserves a full 64 KiB logical slot, including unused padding. Actual GPU vertex/index bytes equal `48 * vertices + 4 * indices`; actual owned buffer bytes are reported separately. Upload staging is exactly that payload size, with all buffer/copy lengths 4-byte aligned. Before allocation, admission reserves the slot plus staging against one geometry total. In-flight staging/retirement can delay an otherwise legal transition. No emergency over-cap fallback allocation exists.

Minimum geometry admission is `(all package pinned-root pages + 1) * 65,536`. The extra full page reserves staging headroom; only one upload is admitted at a time if that minimum leaves no room for a second. The sphere minimum is 131,072 bytes and sheet minimum 196,608 bytes. The selector receives the total cap less one full staging page, then conservatively unions pinned/current/next-cover pages with other scenes' protection. This can leave unused capacity and is intentionally conservative. Normal registered runs use the unchanged 8,388,608-byte geometry pool.

Separate policies are four pending reads, two uploads per streaming tick, 8 MiB metadata plus admitted selection/projection/encoding scratch, and 64 MiB prepared texture texels. Retained package vector capacities, the prepared incoming index's actual capacities, page states, roots and bookkeeping are charged at asset admission. The index is first charged before allocation inside the asset crate's 8 MiB metadata limit; see [the format contract](virtual-format.md). A conservative scene reservation covers models, old/new cuts and demand, active groups, projection/errors, availability, one selector's peak scratch and prepared draw ranges. Scene registrations sum these reservations. This is a conservative element-allocation bound, not allocator headers, thread-stack reservation or process RSS. Texture source mip capacities have a separate 64 MiB CPU bound; GPU mip texels have a 64 MiB policy. Renderer defaults, instance/material buffers, render targets and explicit readbacks are outside the geometry pool and remain visible in renderer ownership/HAL/allocator counters. Default renderer textures use eight texel bytes. Driver memory/residency is not measured by the logical cap.

Virtual transforms use M3's nonsingular finite affine normal domain (max-element condition estimate <= 1e4). Mirroring, nonuniform scale and shear are supported; singular/projective transforms are rejected before virtual admission. Raw M2/M3 APIs keep their previous domain. Projection uses the exact Camera view/FOV/near conventions, a conservative sqrt(matrix 1-norm * infinity-norm) scale bound, sphere near distance, and infinity for near/interior/behind-near cases. A topological maximum enforces the DAG monotone error envelope. Projected error remains a geometric heuristic; it is not an image-error or silhouette certificate.

## Instrumentation and controls

`StreamStats` additionally records actual selector calls, stale Ready drops and cumulative completion/IO collection, resource setup, protection union, stale Ready scan, make-room, upload admission, request scheduling and snapshot durations. Make-room includes nested snapshot work; upload admission includes its successful-upload snapshot. These nested timers must not be added together. The historical `admission` field still covers availability/selection and the upload loop; it excludes several surrounding sections.

The existing advance-section timing sums completion, resources, admission, protection, stale-ready and request durations per application frame before taking percentiles. It excludes the final snapshot and small untimed gaps and is not an independent outer wall timer. Total snapshot duration includes nested observations and cannot be added as an independent stage. Normal admission comparisons and their exact executable/source associations can be reproduced with `scripts/m4-admission-check.ps1`; profiling, page logs and captures are separate from timing runs.

`StreamStats` separates cumulative projection/selection/admission and worker queue/read/verification durations; reads/uploads/payloads; logical peak/current geometry; published/pinned/retiring/staging; actual owned vertex/index bytes; metadata/scratch/CPU-ready envelopes; page states; failures/retries/evictions/in-flight retirements; cut/candidate/visit counts and quality debt. `cut_pages` currently names the selected/pinned/next-demand protected union; exact selected page lists are in `scene.selections()`. It must not be interpreted as only the currently drawn page count. Projection/selection durations are nested inside admission wall time, so do not sum them. `FrameReport` supplies preparation/packing/upload/encoding/submit/poll and renderer GPU timestamp events. Render-pass GPU timestamps exclude upload/IO/acquisition/presentation. `Renderer::stats()` separately reports HAL buffers/bytes and allocator observations, including independent device users; these are not the pool accounting or total driver memory. A published previous legal cut can be retained when it has strictly less projected debt than a new fallback, but only while its output and the union of selected/next-demand/protected pages fit the same total transition budget. Near-crossing bounds can saturate previous debt at infinity. In that case an alternative that loses a previously satisfied, still-required group does not establish an improvement from its aggregate maximum/count alone. Retain the useful resident boundary under the same admission checks, then use the existing bounded retained-cut refinement. This prioritizes an existing required boundary over exchanging it for incomparable saturated debt elsewhere; geometry debt remains explicit. Finite comparisons and the bounded coarsening turns are unchanged. Its debt is recomputed for the new view. A previous cut that already meets the geometric threshold cancels redundant new demand. This publication policy avoids root-quality flashes during IO. If the retained cut still has debt, `select_from_cut` refines its validated active-group set rather than requesting obsolete intermediate root-based representations. At an unchanged view, selection refines the published cut directly with the full remaining candidate allowance. View or transform changes normally start with a root query for coarsening, then share its remaining allowance with retained-cut refinement. The bounded query turns described below handle exhausted allowances. Ordinary candidate exhaustion schedules another pass only after a useful cut publication or a view change. A stalled proposal stays cached until availability or registry state changes. The independent ordered-set selector implements the same initial-cut option separately. This change followed a preserved 3,000-frame near-view run with repeated uploads; the new registered pressure test requires convergence and then 300 quiet frames. `retained_cuts` counts these publications. Selection is cached for unchanged camera/transform/availability/registry state. Cold start and transient debt are observable; a settled view performs no new reads, geometry uploads or selection.

The selector plans past missing intermediate representations and independently publishes complete resident owner closures inside its admitted plan. A seed costs one candidate across both tracks. Every plan/publication transaction fits its output cap and the union of final-plan, published, pinned and protected pages. Publication never generates requests; final demand still includes only the last feasible plan. Quality debt describes the published cut. This removes the proven moving210 blocker where an unrelated missing planned page hid the already-resident orange fin. It does not guarantee arbitrary moving-frame image quality. The earlier coarse-depth ordering correction for cold270 is preserved, with unchanged projection, content, 8 MiB pool and image thresholds.

A placement has one `QueryTurn` byte, initialized to `Ordinary` and released with its scene. A root query that exhausts its positive allowance with candidate debt owes a `Refine` turn. This applies to a newly published root prefix as well as a better retained cut. On the next selection with a positive remaining allowance and an admitted resident previous cut, refinement starts from that cut instead of the roots. It spends the same shared candidate allowance. When this refinement runs at a changed view, it owes a `Rebuild` turn. That turn starts from the roots even if the view has since stopped changing. If rebuilding exhausts the allowance again, one final refinement turn is scheduled at the held view. An unchanged-view refinement then returns to ordinary continuation and caching. A stalled held proposal therefore quiesces instead of alternating forever. Camera and transform changes preserve the owed turn. If the previous cut no longer fits the placement's output reservation or is unavailable, the hint is discarded and root admission applies.

When a root query exhausts its allowance and the previous cut contains an active group whose error is now at or below the threshold, that cut contains redundant detail. The runtime publishes the root query's complete resident fallback instead of retaining the redundant cut, then owes refinement of this new cover. This can temporarily increase projected debt under a forced cap, but avoids permanently pinning fine pages when a capped root prefix cannot yet reach a suitable coarser cut. It spends no extra candidate and preserves the original transition charge. The test covers a fully refined near view, a slightly farther view that still needs some refinement, and a near revisit. Unsaturated root queries retain their existing publication policy.

At cap one, continuously changing eligible queries alternate rebuilding and refining after the first exhausted root query. Each two-query interval gives the published cut one refinement attempt, while every refinement at a changed view is followed by a root coarsening opportunity. Stopping on a refinement turn runs the owed root query on the next tick, so a far view whose minimum cover meets the threshold releases fine detail without another movement event. A far-to-near revisit also refines the newly published root prefix instead of repeating it forever. This is a bound on scheduling, not on IO latency or final image error. After the above-threshold group set stabilizes, each successful resident refinement increases the active set until the threshold or a real capacity limit is reached. Useful publication additionally requires a feasible next owner closure, available or eventually successful requested pages, transition headroom, output space and positive allowance left by earlier placements and scenes. Geometry or output denial can legitimately leave debt with empty demand. Failed reads retain fallback and require explicit repair and retry. Arbitrarily fast view changes and fairness between independently competing scenes are not guaranteed.

A retained refinement with no missing demand can keep the root query's already admitted final plan, or the previous final plan if the root plan has no missing pages. During an owed root revisit that retains the better cover, a still-missing previous final plan takes priority over a competing root plan. This prevents the alternating root turn from canceling useful refinement IO. Every carry rechecks the whole final plan against the actual published cut and protected union. It selects one plan, never combines plans, guesses pages or performs prefetch. A satisfied retained cut cancels redundant demand as before. Availability changes trigger selection. No forced request is made when all admitted plans are already resident.

The scheduling vector allocates one byte per admitted placement and is charged in the existing per-instance metadata reservation. It adds no per-frame allocation or selector query to the ordinary unsaturated path. Candidate counts, later-placement output floors, other-scene reservations, protected page unions and staging headroom are unchanged.

The selector uses the prepared incoming links and per-call cut/page reference counts on both tracks. See [the format contract](virtual-format.md) for its unchanged scratch envelope, cluster-touch definitions, historical oracle and current independent shadow policy. Same-view admission reserves later placements' actual previous outputs because those queries only refine. Reservations also retain each placement's minimum-cover floor, even if a refinement reduces its cluster count. Registry output reservations carry that floor across scenes while reported cut counts remain actual. New views and initial scenes retain minimum-cover reservations, and other scenes' published aggregate output remains reserved. `SelectorMode::SimpleReference` independently uses ordered sets and fixed-point owner closure under the same candidate/output/geometry policies. It does not call the baseline selector. Equal budgets do not imply bit-identical transient IO scheduling or cuts at a given wall time.
