# Virtual geometry runtime

Unit B implements bounded page IO and hardware rendering; M4 and Unit C acceptance remain open. No Unreal or Nanite performance/quality claim follows from this API.

## Ownership and entry points

`virtual_geometry::VirtualAsset::open(cache, manifest, StreamOptions)` performs a bounded synchronous metadata bootstrap. It validates the 80-byte RVM1 manifest, reads only its SHA-addressed package, hashes the actual package bytes, and validates metadata/resources. It never scans or preloads the page directory. A 24-byte header preflight charges encoded metadata together with decoded metadata/validation scratch against 8 MiB before allocating the body; a conservative 1 MiB reservation covers M3 resource containers. Encoded resources and decoded resource storage each have a 64 MiB bootstrap bound, so setup can temporarily hold up to 128 MiB of resource bytes while decoding; retained source mip capacities then have their 64 MiB bound. These setup allocations are separate from the four-slot streaming payload bound and from GPU texture memory. `VirtualAsset::new(package, page_directory, options)` accepts already validated application data but validates/admit-checks it again. The normal runtime dependency graph adds only sha2; the dependency-free asset crate still supplies the owned codec and legal selector. The cooker/importers/codecs remain outside runtime/viewer dependency edges.

The asset owns package metadata, materials/textures, page states, worker and geometry pool. `VirtualScene::from_package(&asset)` uses recorded placements; `VirtualScene::new(&asset, &[VirtualPlacement { mesh, transform }])` admits other placements. A scene owns one persistent M3 `Instances` collection, mesh IDs, legal per-placement cuts and a metadata/output reservation. `scene.set(slot, model)` validates before mutation. Multiple scenes can share an asset. Their selected/demanded pages are unioned, pages are charged once, and aggregate output, candidates and metadata reservations apply across registered scenes. Drops release scene reservations; unprotected geometry is reclaimed under subsequent pressure. Scheduling uses caller scene/placement order, then increasing group/page IDs; fairness between continuously changing independent scenes is not promised. Different assets are explicit independent pools: callers must sum their configured caps. There is no process-global asset registry or implicit global memory cap.

`renderer.try_render_virtual(color, camera, &mut asset, &mut scene, view_mode)` progresses IO/uploads nonblockingly, then borrows page ranges for the same pass as `try_render_view`. `None` means startup/backpressure: retain the prior presented image. Minimum pages also come through the worker. Initial missing/corrupt roots cannot produce an image; a failure after usable roots preserves a legal cover. `asset.advance(renderer, scene, camera, height)` is available for non-rendering wakes; one call is one streaming tick and admits at most two page uploads. Do not call it separately and also render in the same intended tick if the two-upload policy is required per application frame. No ordinary frame waits for IO or queue completion.

Geometry is uploaded once per resident episode: one vertex buffer, one index buffer and one explicit staging buffer per page. Every cluster selects an index-array span, with a per-placement range of the scene's shared instance-ID buffer. There are no cluster geometry copies, cluster instance buffers or retained full-original mesh fallback. M1 raw `Draw`, M3 prepared assets, `CLEAR_COLOR`, shader `TINT`, material/normal/winding behavior, MSAA and transactional reload remain available. Virtual draws are conservatively unculled; offscreen placements still consume their legal minimum/output admission.

## State, IO and completion

Pages have one enum state: missing -> queued -> ready -> uploading -> resident -> retiring -> missing, or queued -> failed. Failed pages retain one fixed 256-byte UTF-8 diagnostic slot and never retry automatically. `failure(PageId)` reads it; after repairing the file, `retry(PageId)` explicitly resets that failed page. Root failure on startup is observable through these same APIs. No error/event history grows without bound.

One worker has at most four outstanding requests, counting active reads, bounded completion-channel payloads and main-thread ready payloads together. It reads at most 65,537 bytes from each page path; exact 65,536-byte extent, real SHA-256, zero padding, attributes and page-local indices pass `decode_page` before publication. The extra byte detects trailing data. Ready data is decoded vertices/indices, not an entire full-detail source. Four retained payloads plus one worker raw/decode overlap have a 327,681-byte element-allocation envelope. Requests/worker bookkeeping are separate small metadata overhead. `cpu_ready_bytes` is main-thread ready-vector capacity; queued completions remain covered by `cpu_io_bound_bytes`, not directly sampled in that field. Delay injection waits on the worker after the actual read/hash/decode and before result delivery. Dropping the worker disconnects completion sends and request receive before join and unparks an injected delay. OS filesystem latency remains outside the application's scheduling control.

The existing three-flight gate remains authoritative, with upload admission below two occupied flights. Renderer submissions have monotonic IDs; `completed_submission()` is a completion watermark independent of the bounded observation queue. An upload records its submission/last use. Published draws update each used page's last use. Staging remains charged until upload completion, and retiring vertex/index buffers remain owned/charged until their last submission completes. A later queue completion proves earlier queue work complete; a dropped caller handle or discarded telemetry event proves nothing. Rendering/reload share the existing timestamp/clear/depth/material/MSAA path. Only explicit evidence capture/final test drains wait for a result.

## Budgets and transform domain

A resident or retiring page reserves a full 64 KiB logical slot, including unused padding. Actual GPU vertex/index bytes equal `48 * vertices + 4 * indices`; actual owned buffer bytes are reported separately. Upload staging is exactly that payload size, with all buffer/copy lengths 4-byte aligned. Before allocation, admission reserves the slot plus staging against one geometry total. In-flight staging/retirement can delay an otherwise legal transition. No emergency over-cap fallback allocation exists.

Minimum geometry admission is `(all package pinned-root pages + 1) * 65,536`. The extra full page reserves staging headroom; only one upload is admitted at a time if that minimum leaves no room for a second. The sphere minimum is 131,072 bytes and sheet minimum 196,608 bytes. The selector receives the total cap less one full staging page, then conservatively unions pinned/current/next-cover pages with other scenes' protection. This can leave unused capacity and is intentionally conservative. Normal registered runs use the unchanged 8,388,608-byte geometry pool.

Separate policies are four pending reads, two uploads per streaming tick, 8 MiB metadata plus admitted selection/projection/encoding scratch, and 64 MiB prepared texture texels. Retained package vector capacities, page states, roots and bookkeeping are charged at asset admission. A conservative scene reservation covers models, old/new cuts and demand, active groups, projection/errors, availability, one selector's peak scratch and prepared draw ranges. Scene registrations sum these reservations. This is a conservative element-allocation bound, not allocator headers, thread-stack reservation or process RSS. Texture source mip capacities have a separate 64 MiB CPU bound; GPU mip texels have a 64 MiB policy. Renderer defaults, instance/material buffers, render targets and explicit readbacks are outside the geometry pool and remain visible in renderer ownership/HAL/allocator counters. Default renderer textures use eight texel bytes. Driver memory/residency is not measured by the logical cap.

Virtual transforms use M3's nonsingular finite affine normal domain (max-element condition estimate <= 1e4). Mirroring, nonuniform scale and shear are supported; singular/projective transforms are rejected before virtual admission. Raw M2/M3 APIs keep their previous domain. Projection uses the exact Camera view/FOV/near conventions, a conservative sqrt(matrix 1-norm * infinity-norm) scale bound, sphere near distance, and infinity for near/interior/behind-near cases. A topological maximum enforces the DAG monotone error envelope. Projected error remains a geometric heuristic; it is not an image-error or silhouette certificate.

## Instrumentation and controls

`StreamStats` separates cumulative projection/selection/admission and worker queue/read/verification durations; reads/uploads/payloads; logical peak/current geometry; published/pinned/retiring/staging; actual owned vertex/index bytes; metadata/scratch/CPU-ready envelopes; page states; failures/retries/evictions/in-flight retirements; cut/candidate/visit counts and quality debt. `cut_pages` currently names the selected/pinned/next-demand protected union; exact selected page lists are in `scene.selections()`. It must not be interpreted as only the currently drawn page count. Projection/selection durations are nested inside admission wall time, so do not sum them. `FrameReport` supplies preparation/packing/upload/encoding/submit/poll and renderer GPU timestamp events. Render-pass GPU timestamps exclude upload/IO/acquisition/presentation. `Renderer::stats()` separately reports HAL buffers/bytes and allocator observations, including independent device users; these are not the pool accounting or total driver memory. A published previous legal cut can be retained when it has strictly less projected debt than a new fallback, but only while its output and the union of selected/next-demand/protected pages fit the same total transition budget. Its debt is recomputed for the new view. A previous cut that already meets the geometric threshold cancels redundant new demand. This publication policy avoids root-quality flashes during IO. If the retained cut still has debt, `select_from_cut` refines its validated active-group set rather than requesting obsolete intermediate root-based representations. Root-based queries remain the coarsening option; both queries share one candidate allowance. The independent ordered-set selector implements the same initial-cut option separately. This change followed a preserved 3,000-frame near-view run with repeated uploads; the new registered pressure test requires convergence and then 300 quiet frames. `retained_cuts` counts these publications. Selection is cached for unchanged camera/transform/availability/registry state. Cold start and transient debt are observable; a settled view performs no new reads, geometry uploads or selection.

The initial selector is still the auditable Unit A scan/closure baseline, with the small necessary `select_with_protected` interface for shared page union charging. No unmeasured traversal accelerator was introduced. `SelectorMode::SimpleReference` independently uses ordered sets and fixed-point owner closure under the same candidate/output/geometry policies. It does not call the baseline selector. Equal budgets do not imply bit-identical transient IO scheduling or cuts at a given wall time.

Persistent viewer (launch only after the foreground-game guard is clear):

```powershell
cargo run -p renderlab-viewer -j 2 -- --virtual-manifest measurements/m4-cook/root-unit-a/closed-sphere.manifest --cache measurements/m4-cook/root-unit-a/cache --cameras measurements/m4-cook/registration-initial/cameras.json --frames 631 --geometry-bytes 8388608 --candidates 1024 --output-clusters 65536 --io-delay-ms 0 --samples 4 --log-frames --validate
```

Omit `--cameras` to orbit/move interactively. `--selector simple` selects the independent control. `--asset <original.rla> --cameras ...` retains the M3 full-detail path. Raw fixture mode still works without either asset flag. Streaming stats are logged with `--log-frames`. The viewer has not been interactively verified by the implementation child; root owns that check.

Finite offscreen replay/capture (no window):

```powershell
cargo run -p renderlab --example virtual-stream -j 2 -- --manifest measurements/m4-cook/root-unit-a/material-thin.manifest --cache measurements/m4-cook/root-unit-a/cache --cameras measurements/m4-cook/registration-initial/cameras.json --frames 631 --capture 0,150,270,330,630 --output measurements/m4-stream/new-sheet --validate
cargo run -p renderlab --example virtual-stream -j 2 -- --mode simple --frames 631 --output measurements/m4-stream/new-simple --validate
cargo run -p renderlab --example virtual-stream -j 2 -- --mode full --asset measurements/m4-cook/registration-initial/closed-sphere.rla --start 150 --frames 1 --capture 150 --samples 4 --output measurements/m4-stream/new-reference --validate
```

Replay defaults are the registered sphere cache/manifest/cameras. `--start`, `--frames`, `--warmup`, `--hold-pose` and comma-separated absolute pose IDs in `--capture` avoid source edits. Warmup repeats the first requested pose and is explicitly extra work. `--hold-pose` repeats the registered start pose for every measured frame; a requested capture of that pose is emitted once at the final frame, and CSV rows retain the original pose ID. This permits a near-view pressure check followed by 300 measured stationary frames without generating a different camera file. Other flags: `--geometry-bytes`, `--candidates`, `--output-clusters`, `--error-pixels`, `--io-delay-ms`, `--samples 1|4`, `--view color|normal|metallic|roughness`. `--mode full` requires the original RLA. JSON dependencies are tooling/viewer only. Output directories must be new; captures are PPM plus raw RGBA8, timings/counters are CSV, and adapter/renderer summaries are retained. Explicit captures serialize their own readback and change scheduling, so capture runs are correctness evidence, not optimized performance measurements. The harness checks the exact VALORANT gameplay process and quiet-window lock before starting and every 60 poses; the helper checks before each child. No desktop capture/input automation is used.

`powershell -NoProfile -File scripts/m4-runtime-check.ps1 -Gpu -Replay -Output measurements/m4-stream/<fresh>` records source/test/executable/content identities, runs format/check/Clippy/CPU and all 13 GPU cases (10 M1-M3 plus three M4), then both original 631-pose replays. Omitting `-Replay` skips dense replay; omitting `-Gpu` runs CPU checks only and explicitly leaves GPU cases ignored. Neither the helper nor runtime makes M4 quality/performance acceptance automatic. Unit C still owes the full capacity/IO matrix, independently quantified registered full-detail/image/motion comparisons, live viewer checks, optimized timings, dev-loop measurements and independent acceptance.
