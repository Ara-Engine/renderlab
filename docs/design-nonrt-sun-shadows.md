# Non-RT sun shadows: depth-map lit rejection with complete geometry rescue

Specification for one implementation unit, based on main `f820af99e585cb31d32189f7875501d77dadfec8`, 2026-11-10. Reading and reasoning only: no builds, GPU lease or new performance measurements. The requested `docs/design-nonrt-performance` is absent from this main; this makes the matching [first recommendation in the visual-bar plan](design-nonrt-under-visual-bar.md#step-1--map-based-sun-visibility-with-selective-world-geometry-rescue) concrete. It does not implement the subsequent lower-rate visibility proposal.

**Build `VirtualLookup::DepthRescue`, initially opt-in. The map may return fully lit; it may never declare a receiver shadowed.** A receiver potentially touched by a shadow boundary, or uncertain for any other reason, gets all of the existing frame's solar-disk directions against world geometry. No map-only soft value, truncated direction mask, new shadow denoiser, or longer history. This narrower first unit targets the expensive lit-but-walked majority and removes N8k's false-dark map result as a possible final answer. It does not assume an empty-looking map or unanimous probes prove visibility.

## First-unit contract

- **C**, current `VirtualLookup::Surface` writes a visibility count consumed by programmable shading; [sampling preparation](../src/virtual_shadow_gpu.rs#L1411) derives direction batches from TR1. **C**, the current budget family is **8/32/64/256 directions**, depending on history/motion, with frame rotation under TR1. Carry this budget and sequence into DepthRescue explicitly: today's preparation excludes Map/Hybrid, so simply inheriting Hybrid would silently retain its old small budget.
- **E**, map acceptance produces exactly `256` in the existing output ABI. Rescued output is the same normalized count `round(256 * visible / K)`, using the production normalization and direction/origin helpers. A zero-sun or uncovered camera pixel follows the existing trivial result.
- **E**, no cached shadow-result table or rolling previous-pixel count in this mode. Evaluate current receivers every frame; retain only world/light-space geometry data. TR1 receives current visibility through ordinary shading and keeps its present rejection behavior.
- **E**, first-unit eligibility: rigid, opaque caster geometry whose complete original cluster set and adjacency are resident. The quarry's original-cluster path is the primary target. Noninvertible transforms, missing geometry/adjacency, unsupported deformation or resource overflow select the **existing named Surface mode for the whole frame before new work begins**. Never omit a caster or quietly replace it by a GI proxy. This preserves existing behavior on unsupported content but leaves that legacy mode's patent flag open.
- **E**, cold/restart frames requesting at least **64 directions** initially keep the current Surface/S4 selection before DepthRescue dispatch. This bounds the first unit: it targets settled still/moving cost without multiplying a new per-ray tree traversal by the cold budget. World map/guard validity survives a pure camera cut; preserving world data is independent of using the old cut algorithm. Extending DepthRescue to cold frames is a later measured choice, not part of its claimed saving.

## Data layout: reuse geometry, do not build another full triangle soup

The existing [map resources](../src/virtual_shadow_gpu.rs#L406) and [page raster](../shaders/virtual_shadow.wgsl#L204) already contain scalar light-space height in their top words. Read the **rasterized scalar height**, not a reconstructed triangle plane. Reuse that encoding and generation/invalidation rules. Disable `vmap_resolve`, `vmap_planes`, `vmap_errors`, legacy min-plane processing and adjacency walks for the new mode. A later allocation cleanup can replace the retained `(height,id)` word with scalar depth; it is not required in the first unit.

| Data | Proposed representation / owner (E unless C) | Lifetime and limit |
|---|---|---|
| Depth | Existing top height, with existing page validity; the ID may remain in storage but is not used to reconstruct an occluder | Reuse existing pages and caster raster. No receiver-dependent barycentric/plane-depth lookup. |
| Boundary guard | Per light texel `u32 edge_height_max`: highest light-axis height of **any potentially silhouette/boundary edge** conservatively covering it; zero means no edge. Height uses the same positive normalized encoding, rounded upward. Ordinary max-reduction mip chain | Cleared/rebuilt with a dirty page and marked valid only when depth, guard and mips share the current generation. Contains caster bounds, not receiver lists or shadow estimates. |
| Mesh rescue tree | Object-space BVH2 over **original caster clusters**, one immutable tree per unique mesh. Internal node: `lo.xyz, left; hi.xyz, right`, **32 bytes**; leaf tag points to an existing cluster record | Original cluster vertices/triangle words remain in their existing buffers. No new per-triangle plane array. Build using CPU cluster bounds, not geometry readback. |
| Rescue instances | World-to-object rows (**48 bytes**), world bounds/root/base words (**32 bytes**) and four metadata words (**16 bytes**); **96 bytes** per instance. Object-to-world matrices remain in the existing model buffer | Update transforms only for rigid movers. Preserve the original source-primitive identity and caster membership. |
| Reasons | `u32` per receiver, bits `INVALID`, `GRAZING`, `NEAR`, `BOUNDARY`, `MAP_BLOCK`, `SEAM`, `UNSUPPORTED` | Diagnostic counts plus routing; clear every frame. Can use the existing scratch/output allocation where lifetimes permit. |
| Queue | Existing tile-coherent packed pixel coordinate plus reason word, **8 bytes/receiver**, counter and indirect args | Capacity is all output pixels. Overflow must invoke the all-receiver rescue path or reject the frame transaction; it must never truncate the tail. |
| Output | Existing visibility target; classifier writes lit candidates, rescue overwrites queued pixels | Separate passes avoid write races. Shading reads it only after rescue completes. |

**E memory arithmetic:** at `1920×1080`, a reason word is `1920×1080×4 = 8,294,400 bytes` and a full queue is `16,588,800 bytes`, approximately **7.91 / 15.82 MiB**. Reuse the existing Hybrid queue where possible. One guard level at **C** `2048²` texels costs **E 16 MiB**; **E** a complete max pyramid adds about one third, or **21.33 MiB/level**, **64 MiB** for three levels. These are incremental allocation estimates before reuse/removal, not measured VRAM. Split base/mips into separate bindings if the selected level count exceeds device binding limits.

**C**, [ClusterInstances](../src/visibility_buffer.rs#L467) already packs **64 bytes/cluster instance** and rejects an oversized storage binding. **E**, an internal-node-only binary tree needs fewer than `N` nodes for `N` cluster leaves: tree bytes `<32N`, below half that existing cluster-record size for the same population. Reusing trees across placements improves this further. Check the actual device limits and total VRAM; do not infer that every other buffer fits from this bound. Keep dispatch dimensions within the device limit using the existing flattened multi-row convention; a queue workgroup must not grow past the legal x count.

Do **not** reuse [software-reflection geometry](../src/reflection_software.rs#L14) without a completeness check: **C**, it skips meshes over `2^19` triangles and [skinned meshes](../src/primary_ray_gpu.rs#L2739). Nor is [GI's cooked far-field cut](../src/gi_bvh.rs#L1) exact contact geometry. **C**, S4 has a scene-size limit and duplicates plane records; **E**, `13,034,903 × 96` bytes is about **1.25 GB before nodes**, already rejected by the earlier plan. The cluster tree removes that duplication while still testing each original triangle in a selected leaf. It is deliberately a modest broad phase, not a new triangle-BVH cook or a claim that its traversal is already fast.

## Passes and routing

### P0: prepare complete caster geometry and a frozen light-space page key

In `ensure_virtual_casters`, retain original-cluster references, excluding appended LOD clusters; the current original-geometry cut corresponds to `refined == NONE` under the existing group-selection contract. Validate each draw's addressed index range is covered once. Build mesh trees once with a median split of cluster-bound centres on the widest axis; split by count when centres coincide so tree depth stays balanced. Tag leaves with the existing cluster index, and reject an unrepresentable index/depth before upload. Append instance transforms in traced placement order. Refit/rebuild is unnecessary for a rigid transform because the ray transforms into that mesh's object space. Transform origin and direction into object space without renormalizing the direction, so world-ray parameter/epsilon remain consistent under nonuniform scale. A flat instance bound scan is sufficient for the first screen, matching the existing software-ray approach; record its visit count rather than inventing a new TLAS project.

First-sitting order: establish cluster/ray admission and the CPU false-lit count gate; add the cached edge guard; add classifier/queue/boolean rescue as a separate module; run the short paired lease. Do not change cook formats, user-material ABI or temporal reconstruction, and do not build optional umbra or lower-rate paths in this unit.

Build the boundary guard from **all caster edges, including those hidden by the nearest depth layer**. A top-layer-only edge detector misses the overhangs and newly revealed secondary blockers that motivated rescue. Use existing original topology/adjacency:

- Ignore a shared manifold edge only when both adjacent face normals are certainly on the same side of **every direction in the supported solar cone**.
- For a world-space normal `n`, cached light axis `L` and cone half-angle `a`, let `b = n·L` and `c = sqrt(max(0, |n|²−b²))*sin(a)`. A conservative sign interval is `[min(b,b*cos(a))−c, max(b,b*cos(a))+c]`. If the two faces cannot be assigned the same strict sign, retain the edge. Boundary, non-manifold and uncertain-degenerate edges are always retained. Grazing faces retain their boundaries; degeneracy/unavailable topology marks the affected cluster region unsafe.
- Raster retained edges as expanded light-space line quads, padding by **E one shadow texel** for raster/rounding uncertainty. Store the maximum endpoint height plus a conservative rounding margin. No conservative-raster extension is required: expanded quads are ordinary geometry. Unknown cluster regions write their projected bound and maximum height instead of disappearing.
- Use the cached sun axis with a guard cone wide enough for the physical disk plus permitted sun hysteresis. If that supported angle changes, invalidate the guard. Query-time dilation adds the receiver-dependent physical penumbra extent; do not bake a screen-pixel penumbra width into the edge atlas.

Implement edge preparation inside the dirty-page/caster work, reusing the currently loaded triangle data and adjacency. It must not reread the entire quarry every camera frame. Measure this extra page-side cost separately. If the old/new depth and guard generations disagree, the classifier sees `INVALID`, not an empty guard. Do not interpolate stored occluder vertices or recover a triangle's depth at the testing pixel.

### P1: classify each full-resolution receiver

Let `t` be world metres per shadow texel at the selected level, `h_r` the receiver-origin light-axis height, and `H` the maximum current caster height. Let `a_eff` contain the physical disk and angular offset from the cached map axis. Start with the entire possible boundary footprint:

`R0 = tan(a_eff) * max(H − h_r, 0) + receiver_footprint_radius + padding`.

**E**, start with padding **two shadow texels** in addition to the raster guard. Derive receiver footprint conservatively from camera pixel scale and its geometric plane; force rescue at a view-grazing/ill-conditioned footprint. This is independent of whether a few probe rays happened to encounter a blocker. If any footprint page is absent, stale, outside coverage or from another level generation, select a fully valid covering coarser level; if none exists, `INVALID`.

Query the maximum edge height over the **whole square covering this disk**, not sparse point taps. A covering-mip query can cover it with at most a small fixed set of aligned cells; include all cells touched and their border. If its upper bound is still uncertain at the chosen query budget, rescue. An optional bounded refinement can shrink the radius using the maximum edge height actually found; start from `R0`, never from zero blocker evidence. An unrepresented thin caster must not get a zero-radius test.

The decision is deterministic from current geometry/depth and validity:

```text
if no receiver or sun disabled: existing trivial output
else if thin/back-side receiver, not certainly sun-facing, or view grazing: RESCUE(GRAZING)
else if any required depth/guard page is invalid: RESCUE(INVALID)
else if the continuous-cone footprint may reach a retained boundary above the origin:
    RESCUE(BOUNDARY)
else evaluate fixed 2×2 central-depth comparisons at the receiver:
    use receiver-plane depth at each texel centre, plus the existing geometric epsilon
    if coverage/precision/receiver-plane evidence is inconsistent: RESCUE(NEAR)
    if ANY comparison says blocked: RESCUE(MAP_BLOCK)
    otherwise: MAP_LIT (=256)
```

The receiver-plane correction is evaluated from the **receiver's** world point/geometric normal; it is not an occluder-plane reconstruction. **E**, require the production-oriented geometric normal to satisfy signed `n·L > sin(a_eff)+0.05` for the lit shortcut; otherwise rescue. Using the absolute dot here would incorrectly admit sun-back-facing surfaces. Validate the margin in the screen. Do not enlarge normal/depth bias by a shadow texel to make a false-dark score disappear. Specifically, for each fixed depth texel compute `delta = stored_height − receiver_plane_height_at_texel`. Accept an open comparison only for `delta <= existing_epsilon_in_light_height + rounding_error`; any positive excess takes geometry, with a `NEAR` diagnostic reason when it is within **E two shadow texels**. Mixed empty/covered taps, unreliable receiver-plane gradients or an error bound exceeding the current geometric epsilon also take geometry. Depth agreeing with the receiver plane is the ordinary self-surface case, not by itself a reason to rescue every flat floor. This rule does not ignore a placement, its peel, or a differently raised surface. Geometry-boundary completeness and the small numerical tolerance must still pass the full-geometry audit.

The central comparisons do not filter a soft answer: they only veto a fully-lit shortcut. No fast-umbra path in this unit. All map blocks, all penumbrae and all boundary/fringe uncertainty go to geometry. This is the specific answer to N8k's lit-darkened limit and the failed umbra work screen.

### P2: guard routing boundaries, then compact a coherent queue

Expand the receiver rescue mask by **E one screen pixel**, respecting receiver coverage. It is an extra classification guard, not screen-space lighting: all shadow evidence still comes from world geometry/light-space caster data. Screen edges and disocclusion have no missing off-screen shadow input. Keep one final reason word per receiver and compact once per trace tile using the existing Hybrid queue pattern. With **E 32 lanes/group**, let `W=ceil(queue_count/32)`, `x=min(W,device_max_x)`, `y=ceil(W/max(x,1))`, `z=1`; flatten with the actual `x` stride and range-check the queue index. A zero queue emits a zero-work dispatch. Reject an impossible y/storage capacity rather than clipping it.

The new mode must not blend a map shadow estimate into a geometry penumbra. In the mask's outer audit halo, compute geometry as well and compare with the proposed lit endpoint. **E**, require agreement to the count quantization, initially **one part in 256**, before keeping the classifier. If the halo remains partially shadowed, its guard was too small or incomplete: widen/fix it and rerun the screen. Do not feather away the lost shadow, add history inertia, or ship a visible binary routing contour. The intended handoff is between the same fully-lit endpoint on both sides; world-anchored guards and a fixed query pattern prevent a separate animated noise band.

This is a design for conservative geometry-derived routing, not a proof that arbitrary raster precision, malformed meshes or topology omissions cannot leak. The critical pre-build/first-lease test is whether its unrescued set actually contains no visible missed fringe. Unanimous central samples alone do not meet that condition.

### P3: full world-geometry rescue, then publish the count

Use a separate engine-only compute module, not another copy inside every user material shader. Process one queued receiver per lane/chunk and keep the existing `K`, seed, sequence rotation, geometric epsilon, source-front/thin handling and actual light-disk angle. The physical disk does **not** grow by the map's hysteresis margin: only the classification guard grows.

Traverse the complete instance/cluster trees against those rays; test every candidate original triangle with a **boolean 3D plane/edge any-hit** predicate using [S4's math contract](../shaders/sunvis_s4.wgsl#L61) / [CPU twin](../src/sunvis_s4_math.rs). Derive support/edge planes in registers from the loaded triangle; do not store another plane soup. Return blocked/unblocked only: no barycentric coordinate weights, interpolated occluder depth, closest-hit reconstruction or shading callback is needed. AABB interval tests are broad-phase culling, not a map-texel geometry-consistency walk. Traverse both faces as the current opaque shadow contract does.

Do not call `rs_trace`/`rs_blocked` unchanged: they compute barycentrics and hit distance, and their geometry is incomplete for this purpose. Do not append `virtual_shadow.wgsl`'s legacy march to the new module. Use a validated bounded-depth tree/stack with a complete overflow traversal, or reject its admission before rendering. A per-frame cost cap may choose the old **whole-frame** mode before work; it may not manufacture a result for untested rays. Queue overflow similarly never means lit, umbra or reusing a stale count.

Use explicit vector-component stores in WGSL (avoid the known NVIDIA/naga dynamic vector-store trap), and avoid passing the tree/large arrays by value to hot helpers. Write each receiver's final count once after all of its directions finish, then shade normally. The shader gets visibility, not a baked BRDF/albedo/diffuse result. Toon and custom light loops remain programmable; no new user-program edits or material pipeline variants are required.

## Penumbra width, cuts and movers

**Penumbra width:** a boundary at light-axis distance `d` can affect a receiver out to approximately `d*tan(a)` in light-space transverse distance. The guard uses the full cone and conservative height bound, with texel/receiver margins. It cannot restrict its search to a central ray's blocker distance, the map's nearest layer, or a probe list. All pixels within that potential support get the unchanged disk samples and visibility integration. Wide suns therefore enlarge the **rescue set**, rather than being made artificially narrow by a fixed PCF radius, smaller ray count or walk cap. Multiple blockers are resolved by actual per-direction geometry. If wide-sun rescue dominates, report the performance miss or retain the old mode for that workload.

**Camera cuts:** reset only screen history/reconstruction as required by the existing path, not the world depth/guard or immutable mesh trees. Scroll/invalidate pages only when their world/light coverage changes. In this first unit the CPU cold-budget selector uses today's Surface/S4 path, before classifier/queue work; its shadows and cost should remain the baseline. Newly revealed pixels on ordinary moving frames require valid current pages or full geometry, never previous visibility. Keep guard dirtiness even while the legacy path is selected. On first activation or returning to DepthRescue after a window-changing cut, rebuild the required guard pages from all casters before marking them valid; any pages not yet ready force complete rescue. Record this first-return cost separately from warmed steady timing and inspect the whole recovery sequence. The first unit does not promise that this refill is free. A future cut extension may use DepthRescue only after pricing its high-`K` queue; it must not show a dark/bright first frame while the guard refills.

**Rigid moving objects:** keep object-space trees; update instance transforms/current bounds before either map work or rescue. Invalidate the union of old/new light-space page bounds for **depth and edge guard**, including border/mip dependencies. Clear old guard edges even after a caster leaves; an atomic max without a dirty-page clear would leave permanent phantom rescue. Because the classifier runs each frame and the guard represents all caster edges, moving shadows do not wait on a world shadow-result cache. Current shading sees the new count immediately.

**Skinned/deforming, streamed or unknown geometry:** the existing reflection/S4 shortcuts do not cover these reliably. First unit selects the old whole-frame path when complete current geometry/bounds cannot be certified. Do not suppress the caster, trace rest pose, or declare a missing page empty. Supporting posed cluster trees/bounds and late streaming admission is a separate retained step. This is an explicit eligibility limit, not a claim that the non-RT renderer no longer supports those scenes.

## Cheapest rejection screen and one short lease

**Before a renderer build:** recover the already inspected Map/Hybrid/Surface quarry frames and the S2 wide-sun fringe failures. If the old raw receiver/map buffers are gone, say so; do not invent replay counts. CPU replay a sparse set of their worst pixels plus a regular whole-image lattice against full geometry. Evaluate the actual cone/edge routing, including pixels outside the old probe list. Count `q = rescued/covered`, false-lit shortcuts, halo endpoint disagreements, instance/node/triangle visits and projected dirty guard work. Record counts separately for still, moving, rigid mover and wide sun. A classifier that cannot route every known false-dark/fringe/contact case to rescue is rejected before performance work.

Check original-cluster coverage and tree/storage limits in this replay. Reject the chosen representation if it needs another full quarry triangle soup, relies on the coarse GI cut, or loses off-screen casters. **E initial cost stop:** if the screen rescues substantially more than **20–25%** of covered still receivers, or the counted rescue work approaches today's complete lookup, do not build a large optimization around it; try a tighter *conservative* boundary query first. This is an economic screen, not permission to drop the excess pixels.

**One lease, under E 15 minutes, with the test binary already built and pipelines warmed before paired timing.** Run one process, load the quarry once. Keep the old mode, new mode, route-audit mode and existing map-only diagnostic available in that binary. Avoid timing cold shader compilation; log warm-up identity and rerun the CPU-safe preflight before the lease, not inside it. Suggested allocation:

| Lease segment (E budget) | Smallest work that decides it |
|---|---|
| About 2 minutes | Warm both paths/variants, verify the named pass log and original-sun settings. Reject invalid geometry/guard generations immediately. |
| About 5 minutes | Old/new paired still → slow lateral camera motion across contact edges → camera cut → settle, at native 1080p. Capture a small set of full frames plus shadow-contact and lit-ground crops, reason mask and counts. Time page+guard, classifier, queue, rescue, total shadow work and frame span separately. |
| About 3 minutes | Same loaded scene: move one rigid boulder through the view and off-screen; turn the sun enough to cross the page key. Check old and new shadow positions, old/new page footprints and guard clearing. |
| About 3 minutes | Small S2 wide-sun motion shot plus thin-strip/contact-fold crop using existing harness scenes; inspect the previously **unlisted** fringe, not only the queue. |
| About 1 minute | Inspect the side-by-side sequence at normal display scale and selected difference/reason crops; leave a short JSON/timing summary. Stop at the first deciding failure rather than expanding the campaign. |

The per-segment budgets sum to **E 14 minutes**; this is a planned screen, not a claim it already ran. A second broad quality campaign is justified only after this small screen retains a variant. RT receives a short unchanged-path smoke/identity witness as part of the retained implementation's normal checks; this docs unit runs none.

**Pass/fail look-for list:**

- **Leaks / missed fringe:** no new sunlit specks in gravel/crevices, no unshadowed thin pole/leaf-sized blocker, no light slit when an off-screen caster still shadows the receiver. Audit accepted-lit pixels against geometry; a false-lit result in a visible fringe fails routing.
- **Lit darkening / acne:** the map never writes a shadow. Inspect N8k's lit top edge and thin strips; a darker result now identifies geometry/origin disagreement and must be explained, not hidden with bias.
- **Peter-panning / contact loss:** no detached shadow at boulder feet, door base or the contact fold; use original geometry and current epsilon. Inspect both caster and receiver motion.
- **Shimmering / routing seams:** no crawling line on clipmap/page boundaries, no stippled halo where a receiver enters rescue, no one-frame map/guard mismatch, and no pulse when the camera stops or a moving caster leaves its old bounds.
- **Penumbra collapse:** preserve the entire S2 wide-sun fringe and the width/gradient from contact to far shadow. No dots of zero/one visibility replacing a smooth penumbra. Compare the sequence against current Renderlab, RT/reference and matched Unreal; no longer history, smear or ghost trail is a substitute.
- **Cuts / first frames:** first-unit cold fallback must retain the current sequence with no new spike from building a guard or tree inside the cut. Newly revealed ordinary-motion pixels must receive current visibility immediately.
- **Performance / memory:** retain only if paired total shadow **and** frame time improve on the enabled workloads with no visible regression. Count extra page work and memory, not just the rescue kernel. A new allocation beyond device limits, hidden CPU rebuild per moving frame, or an unaccounted compiler stall fails the screen.

## Honest cost estimate and stopping rule

**E model:** `Tnew = Bdepth+guard+classify + Oqueue + q*Cgeometry`. `Cgeometry` is the cost the **new** cluster rescue would have at full receiver coverage with the same `K` and ray distribution. It is not today's Surface time, and not S4's measured game cost. Query coherence, cluster size, per-instance scans and early exits can make `q*C` nonlinear; retain a fixed queue floor in the estimate.

For settled original-sun quarry, **E planning ranges**, not measurements (including the old queue-floor warning rather than assuming it vanishes): `B = 0.35–0.75 ms`, `O = 0.50–0.90 ms`, `q = 0.05–0.15`, `C = 8–16 ms`. Therefore **E** `Tnew = 0.35+0.30+0.05*8` to `0.75+0.70+0.15*16` = **1.25–4.05 ms**. Against **M P-STILL 4.2 ms**, saving is **E 0.15–2.95 ms**. A useful central illustration is **E** `0.55+0.65+0.10*12 = 2.40 ms`, saving **1.80 ms**, about **43%** of that pass. This is not a promised 0.50 ms shadow system.

A rescue fraction of **E 0.25** at the high cost assumptions gives `0.75+0.90+0.25*16 = 5.65 ms`, a clear loss. That is why the first action is the geometry/routing count, not committing to a new default. Moving receivers generally use more directions and may select harder queries; allow **E roughly 1.5–7 ms** until a matched queue measurement narrows it. Moving casters add dirty depth/guard pages; the old map's extra **M 0.53 ms** plane-resolve bill is not a measured saving for the new edge pass. Cold frames select the baseline algorithm without new guard/tree work; first activation and post-cut first-return guard cost still need measurement and can fail the recovery gate. No saving against the **M 43.11 ms whole-frame cut** is claimed.

For the **M P-STILL 1.75×** still slowdown, write the current frame as `1.75*Ue`. Beating Unreal requires a saving greater than **E `0.75*Ue`**, not merely a faster sun pass. Using **M P-STILL 7.03 ms** and its **M P-YARD comparator 4.02 ms**, the direct parity saving is **E `7.03−4.02 = 3.01 ms`**; the central shadow estimate saves only **1.80 ms**. Holding all other work fixed would give **E `7.03−4.2+2.40 = 5.23 ms`**, still slower than Unreal. The estimated shadow range gives **E 4.08–6.88 ms whole-frame**, not a measurement. Parity through this pass alone would require **E `4.02−(7.03−4.2) = 1.19 ms`** for shadows, below even the optimistic end of this planning range; other non-RT work remains. Keep a smaller visible-quality-preserving win, per Milestone 8.

**Switch rule:** if the guard is too expensive or too broad, first tighten its conservative mip/height query and improve queue coherence using the captured counts. If known fringes remain unrescued, stop the shortcut and retain complete geometry for that workload. Do not reduce the cone, cap directions, resurrect the old probe list, or rename the legacy marcher as a cleared rescue. Certified umbra shortcuts, PCSS soft-map answers, lower-rate evaluation, dynamic tree refits and a new shadow temporal cache are subsequent units, not requirements for this first sitting.
