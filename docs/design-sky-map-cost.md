# Showcase sky-map shading: causes to screen next

Reading-only follow-up to [the cut study](design-cuts.md), against main **`73eee447f0617ef410fa4e1c45220196a808b49c`**, after **v0.1.3**. No builds, GPU work or new measurements. **M** means measured in the linked repo report; **R** means reported by repository code or a named source, not a timing measurement; **E** means an estimate or proposed screening parameter. Identifiers and line numbers are not measurements.

**Start with a post-banking hit/miss lookup split, then inspect the generated shader's handling of an overwritten sky value.** The dominant hypothesis is repeated manual environment filtering inside glossy-ray and hit shading, rather than the sky background itself. Do not lower glossy ray counts as the first way to make that lookup cheaper: count also changes each ray's cone and the reflected highlight/noise problem.

## Establish the right baseline

**M — [P-SHOW2 §3](p-show2.md#3-skymap-the-top-cost-root-steer-2-half-fixed):** Showcase, native **1080p**, RTX **4070 SUPER**, Ara release player; shared-machine single captures, not a quiet paired campaign. Different timestamp spans are deliberately separate below.

| M RT configuration | Ara render span, ms | Deferred shading, ms |
|---|---:|---:|
| Legacy map before narrow-level banking | 52.48 | 43.60 |
| Map after banking, still | 33.89 | 25.10 |
| Map after banking, moving | 33.14 | 27.77 |
| Constant sky on the head, still | 19.74 | 8.50 |

**E subtraction:** remaining shading premium `25.10 − 8.50 = 16.60 ms`; banked-map Ara span premium `33.89 − 19.74 = 14.15 ms`. These do not agree exactly because they are different boundaries and samples. The coordination brief's **R 11–13 ms** constant-sky frame belongs to an earlier integration/build context; it is not the same-process denominator for the **M 33.89 ms** capture. P-SHOW2 explicitly records that build/run spread. Do not advertise a precise speed ratio by dividing those unmatched totals.

**M diagnostic ablations before banking:** map shading **43.60 ms**; reflections off **5.34 ms**; GI off **37.43 ms**; escaped glossy rays using a constant **29.36 ms**. Thus **E** switching that escaped-ray lookup site removes **14.24 ms**, while reflections-off removes **38.26 ms**. These are cost-only altered images and overlapping effects, not shippable candidates or post-banking attribution. Source-level placement of `rl_sky` before hit selection also means the escaped-ray switch is not proof that all removed work executed only on misses. Repeat the split on the shipped layout.

P-SHOW2 already fixed the worst narrow-mip seam path: CPU `bank_legacy` resamples small legacy levels into **R code 32×32** array faces ([`environment.rs:150–187`](../src/environment.rs#L150-L187)); original large levels keep their mips. **M** banking saved shading **43.60 → 25.10 ms**, with full-image maximum difference **2 codes** in that screen. Recommending that upload change again would double-count shipped work. The integration thread's independent-roughness map also retained a substantial premium (**R reported in P-SHOW2: 23.8 vs 8.9 ms** shading), weakening “legacy seams explain everything”; it is not a controlled attribution experiment.

## The call chain and the likely multiplication

[`rl_reflection_prepare`](../shaders/reflections.wgsl#L134-L211) runs before the primary program's `shade`. **R code:** the declared lobe selects a mirror ray or glossy `ceil(48 × roughness)`, clamped **4–16** rays; valid strata trace geometry, then shade hits with the program's `surface`/`shade`. The software composition replaces the traversal through [`program.rs:129–138`](../src/program.rs#L129-L138), so lookup improvements can benefit both paths without changing their traversal or material interfaces.

On an escaped ray, [`rl_sky`](../shaders/reflections.wgsl#L70-L73) calls `environment_reflection(direction, cone roughness)`. On a hit, [`program.rs:488–496`](../src/program.rs#L488-L496) selects open indirect state; arbitrary user shading can read diffuse irradiance and/or `indirect_radiance`. [`environment_lobes.wgsl:38–48`](../shaders/environment_lobes.wgsl#L38-L48) still performs the open-map specular lookup before adding any cache bounce. “GI off” therefore does not remove the sky lookup from reflection-hit shading.

[`program_api.wgsl:112–121`](../shaders/program_api.wgsl#L112-L121) transforms world directions to map space and calls [`scene.wgsl:253–388`](../shaders/scene.wgsl#L253-L388). The latter selects a cube face, selects roughness levels and manually cube-bilinearly filters texture-array data. **R code:** ordinary bilinear uses **4** `textureLoad`s; interpolating **2** roughness levels normally uses **8**, with extra work at edges/corners. The exact-zero blend / fully rough cases already skip the second level. GPU textures are **R code RGBA32F / 16 bytes per texel**, [`environment_gpu.rs:255–301`](../src/environment_gpu.rs#L255-L301), deliberately using `textureLoad` without optional float-filtering features ([`:211–215`](../src/environment_gpu.rs#L211-L215)).

**E upper sizing example:** at **M 1920×1080** output, if **E every pixel** launched **R code 16** valid rays and each required **R code 8** texel loads, `1920 × 1080 × 16 × 8 = 265,420,800` logical texel loads per frame. At **R code 16 bytes**, that is **E 4.25 GB** of logical fetched texels before hit shading's further lookups. This is deliberately not a DRAM bandwidth measurement: eligibility, misses, zero-weight levels, cache/coalescing and repeated addresses can reduce actual traffic greatly. Count real lookup sites and rays before using this bound in a bandwidth argument.

## Ranked causes and the cheapest discriminating test

The ranking is **E likelihood / usefulness of a cheap test**, not measured attribution. Timing switches must preserve identical geometry, materials, ray strata, cones and hit shaders unless the row explicitly labels a cost-only ablation.

| Priority | Hypothesis and source evidence | Cheapest screen / what would reject it |
|---|---|---|
| First | **Repeated manual filtering at ray misses and hit programs dominates.** The ablations above localize most of the old premium to reflection work; every hit can call more than one environment input. The constant branch replaces texture/address/filter instructions with a uniform value. | On the shipped banked layout, separately replace only escaped-ray sky reads, hit-program environment reads and primary environment reads with constants, as cost-only switches. Count calls/roughness levels in a separate diagnostic run, not the timed shader. If only primary reads matter now, reject the per-ray attribution; if both hit and miss sites matter, optimize their common lookup helper. |
| Second | **The miss-sky expression may execute even when a hit overwrites it.** [`reflections.wgsl:192–200`](../shaders/reflections.wgsl#L192-L200) initializes `radiance = rl_sky(...)` before the hit branch replaces it. Generated code may already sink or predicate the pure lookup; WGSL placement alone does not prove wasted loads. | Inspect available compiled-shader disassembly first. Then move sky evaluation into an explicit miss `else`, changing neither hit shading nor returned values. Test the software string composition too: its exact replacement template contains this code. Reject if generated code/timing is unchanged. This is the smallest potentially image-equivalent fix; do not forecast a millisecond saving without finding executed loads. |
| Third | **RGBA32F/manual filtering throughput or latency limits the hit/miss-heavy kernel.** The common path issues the loads above; large independent-roughness banks can widen the working set. P-SHOW2 reports about **R 25 MB** of full-face banks for its independent layout, while the legacy bank addition is only about **R 0.9 MiB maximum**. They are different layouts, not one shared working-set measurement. | First vary only environment face/bank dimensions in a diagnostic input, preserving layout and shader/ray counts; then compare a finite same-layout constant-valued map with the gradient map while keeping map sampling enabled. Use texture/cache stall counters if already available. Next screen an RGBA16F upload/manual-load variant with range-aware encoding; reject if timings barely respond to dimensions/format. Halving texel bytes is **E 50% logical-byte reduction**, not a promise of half the shading time. |
| Fourth | **Residual seam/bank divergence or redundant face/level work remains.** Banking reduces seam frequency but does not delete remap branches, roughness-level selection, texture selection or repeated direction transforms ([`scene.wgsl:280–351`](../shaders/scene.wgsl#L280-L351)). Small legacy levels and independent banks have different access patterns. | Count in-face/edge/corner and one-/two-level visits separately. On a diagnostic copy, clamp all taps inside the selected face to bound seam overhead; this is visibly wrong at seams and never ships. If its timing is flat, stop seam work. Otherwise share face/address computations across the two levels and consider seam gutters; verify rotations through face edges and corners. |
| Fifth | **More texture instructions cause register pressure, spills or serialized divergent hit shading, rather than raw bandwidth saturation.** The map adds texture/address logic inside a ray-query loop with per-hit parameter changes; constant folding removes much of it. P-S4's replay results elsewhere show that apparently reusable work can lose to compiler/occupancy effects; they are not measurements of this shader. | Compare compiled register/local-memory use and occupancy for the same map/constant compositions. Isolate the common helper without changing arithmetic or sample count and examine generated code. Reject this cause if resource use and issue/stall evidence do not change. Splitting traversal/shading into queues is a later, larger option only after this evidence exists. |

**Format changes need a quality gate.** Raw half precision can overflow bright HDR texels and change highlights; global scaling/exposure encoding must preserve dynamic range before multiplication. Hardware filtering is a separate capability/layout proposal, not something the current RGBA32F array code already supports. A same-layout constant-valued **map** still exercises map indexing and texture loads; switching to the renderer's constant-sky mode does not. A compiler-folded “constant texture” replacement would invalidate that diagnostic.

Do not replace arbitrary hit shader calls with the primary material's BRDF, reuse a primary's lookup for a different hit direction, or reuse a roughness level without checking the cone. Those shortcuts would either break programmability or alter the reflected image. Count reduction is already studied in [design-glossy-rate.md](design-glossy-rate.md); keep its fixed-cone control if it is used as a cost diagnostic, because reducing count alone widens each stratum's cone.

## One short first screen

**E proposed lease: 12 minutes**, one loaded Showcase, RT first, prebuilt variants only. Record pass times with `RENDERLAB_PASS_LOG` and use adjacent baseline/control samples within the same process; separate cold-pipeline setup from warmed shading. Run unchanged map, renderer constant, same-layout constant-valued map, miss-only constant, hit-only constant and explicit-miss-branch variants. Treat the altered-lighting controls as attribution tools, not acceptance images. Preserve the constant/map raw HDR comparison and full final image for the potentially equivalent branch-only change.

**E pass/fail look-for list:** accept a branch-only optimization only if it lowers warmed shading without new seams, moving highlight pulses, lost sky detail or changes to user shader dispatch. For half-format/address variants, inspect HDR sun highlights, rough metals, mirror faces, map rotation through corners and immediate camera motion; reject white clipping, dark seams, banding or temporal sparkle. A successful RT screen still needs the same lookup change screened on non-RT, where traversal may hide or magnify its cost.

No new resampling, temporal reuse, denoising or irradiance-cache ranking is proposed by these first screens; the existing flagged sun method is unrelated and remains flagged as described in [the cut study](design-cuts.md#patent-checks-for-the-borrowed-parts). This is not a patent-clearance claim for future sampler/encoding implementations.

Reading alone cannot determine executed texture-load counts, hit/miss ratios after banking, register spills, cache behavior, the optimal texel format, or which change is visually safe. The first outcome needed is a post-banking attribution split; the old miss-ablation saving is not a budget available to claim again.
