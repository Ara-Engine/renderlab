# Showcase sky-map shading: causes to screen next

Standalone expansion of the initial note in [the cut study](design-cuts.md), against main **`7bd8b9a`**, after **v0.1.3**. No builds, GPU work or new measurements. **M** means measured in the linked repo report; **R** means reported by repository code or a named source, not a timing measurement; **E** means an estimate or proposed screening parameter. Identifiers and line numbers are not measurements.

**Start with a post-banking hit/miss lookup split, then inspect the generated shader's handling of an overwritten sky value.** The dominant hypothesis is repeated manual environment filtering inside glossy-ray and hit shading, rather than the sky background itself. Do not lower glossy ray counts as the first way to make that lookup cheaper: count also changes each ray's cone and the reflected highlight/noise problem.

## Establish the right baseline

**M — [P-SHOW2 §3](p-show2.md#3-skymap-the-top-cost-root-steer-2-half-fixed):** Showcase, native **1080p**, RTX **4070 SUPER**, Ara release player; shared-machine single captures, not a quiet paired campaign. Different timestamp spans are deliberately separate below.

| M RT configuration | Ara render span, ms | Deferred shading, ms |
|---|---:|---:|
| Legacy map before narrow-level banking | 52.48 | 43.60 |
| Map after banking, still | 33.89 | 25.10 |
| Map after banking, moving | 33.14 | 27.77 |
| Constant sky on the head, still | 19.74 | 8.50 |

**E subtraction:** remaining shading premium `25.10 − 8.50 = 16.60 ms`; banked-map Ara span premium `33.89 − 19.74 = 14.15 ms`. These do not agree exactly because they are different boundaries and samples. The coordination brief's **R 11–13 ms** constant-sky frame belongs to an earlier integration/build context; it is not the same-process denominator for the **M 33.89 ms** capture. P-SHOW2 explicitly records that build/run spread. Do not advertise a precise speed ratio by dividing those unmatched totals.

**M diagnostic ablations before banking:** map shading **43.60 ms**; reflections off **5.34 ms**; GI off **37.43 ms**; escaped glossy rays using a constant **29.36 ms**. Thus **E** switching that escaped-ray lookup site removes **14.24 ms**, while reflections-off removes **38.26 ms**. These are cost-only altered images and overlapping effects, not shippable candidates or post-banking attribution. Source-level placement of `rl_sky` before hit selection also means the escaped-ray switch is not proof that all removed work executed only on misses. Repeat the split on the shipped layout.

P-SHOW2 already fixed the worst narrow-mip seam path: CPU `bank_legacy` resamples small legacy levels into **R code 32×32** array faces ([`environment.rs:150–187`](../src/environment.rs#L150-L187)); original large levels keep their mips. **M** banking saved shading **43.60 → 25.10 ms**, with full-image maximum difference **2 codes** in that screen. Recommending that upload change again would double-count shipped work. The integration thread's independent-roughness map also retained a substantial premium (**R reported in P-SHOW2: 23.8 vs 8.9 ms** shading), weakening “legacy seams explain everything”; it is not a controlled attribution experiment.

## What selecting the map actually changes

[`Engine::create_environment`](../src/engine/mod.rs#L552-L562) uploads a **prepared** map; it is not a per-frame environment integrator. [`apply_lighting`](../src/engine/mod.rs#L901-L940) selects that handle and its yaw/intensity for `Sky::Map`, whereas `Sky::Uniform` supplies a constant through [`settings::lighting`](../src/engine/settings.rs#L230-L239). Visible-map background is another switch, distinct from illumination: keep it fixed while testing lighting costs.

[`try_upload_environment`](../src/environment_gpu.rs#L211-L415) creates diffuse/specular textures and the optional independent-layout lobe table at upload. [`EnvironmentState::uniform`](../src/environment.rs#L102-L124) sends the shader yaw, intensity and a signed layout/level marker; [`set_environment`](../src/environment_gpu.rs#L450-L462) retains the same selected handle without re-uploading pixels or incrementing generation. The renderer can receive the same `Sky::Map` every frame without reconstructing the map. If an embedder creates a **new handle** every frame, that is a different failure; log generation and upload counts to detect it rather than assuming it.

The important hot-path differences are these:

| Source path | Constant | Map |
|---|---|---|
| [`gi_open_irradiance`](../shaders/gi_api.wgsl#L153-L157), used by reflection hits with open indirect state | Uniform RGB times pi. | Direction transform and manual diffuse cube-bilinear lookup. |
| [`indirect_radiance`](../shaders/environment_lobes.wgsl#L38-L48), used by the primary and the hit program | Uniform RGB plus any current bounce. | Prefiltered specular map lookup, then current visibility/bounce. Disabling the receiver cache does not eliminate this lookup. |
| [`rl_sky`](../shaders/reflections.wgsl#L70-L73) | Uniform exposed RGB. | Prefiltered lookup at the ray's own sub-cone roughness. |
| [`standard::shade`](../shaders/programs/standard.wgsl#L104-L132) | No environment-lobe loop. | Optional dominant-lobe evaluation and share subtraction for independent-layout maps. Legacy maps have no fitted lobes. It computes the primary's untraced estimate before blending traced incident light, even when the traced share replaces it entirely; whether the compiler discards that work is another code-generation question. |
| [`gi_sky`](../shaders/gi_cache.wgsl#L786-L802), cache fill/integration | Unit-radiance integration, scaled at lookup. | Samples the prepared map for cell integration. This is GI pass work, not automatically deferred-shading cost. |

**Extra-ray/cache hypothesis:** the reflection eligibility/count code in [`reflections.wgsl:134–159`](../shaders/reflections.wgsl#L134-L159) depends on declared lobe, roughness and `ReflectionSettings`, **not** `environment_enabled()`. [`program::reflection_api`](../src/program.rs#L85-L107) selects traversal from shader hooks, stage and hardware/software head, independently of sky type. No map-only extra reflection bounce or per-pixel importance-ray pass was found. Reflection hits already use the open environment on **both** skies; the expensive map lookup replaces the cheap constant there. It is not a map-only cache-disable switch. If an application changes render settings or material programs along with the sky, that separate change must be logged.

Map identity/yaw/content changes can cause GI re-integration and relighting ([`gi_cache.rs:2319–2398`](../src/gi_cache.rs#L2319-L2398)); a stable map does not require that work forever. P-SHOW2's false held-skin relight has already been removed. An upload/reintegration regression could explain an unstable total frame, but a GI timestamp increase cannot simply be assigned to the isolated shading premium.

**CDF/importance-search hypothesis:** [`RadianceProposal::sample`](../crates/cook/src/environment/specular.rs#L75-L80) really does search a luminance CDF, but it is Rust in the CPU **cooker**, used to prepare the field. Dominant-lobe quadrature in [`environment_lobes.rs`](../src/environment_lobes.rs#L195-L295) also prepares upload data. The runtime reflection sampler is a fixed-count analytic GGX VNDF, [`reflections.wgsl:57–67`](../shaders/reflections.wgsl#L57-L67), followed by direct texture-array lookup; the WGSL map bindings carry prepared textures/lobes, not that CDF. Thus a per-pixel CDF search is **ruled out by this runtime call graph** as an explanation of steady shading. The cheapest confirmation is a call-site/binding audit plus unchanged cooker/upload counters through the held capture; spending a GPU lease removing the cooker's CDF would test the wrong stage.

## The call chain and the likely multiplication

[`rl_reflection_prepare`](../shaders/reflections.wgsl#L134-L211) runs before the primary program's `shade`. **R code:** the declared lobe selects a mirror ray or glossy `ceil(48 × roughness)`, clamped **4–16** rays; valid strata trace geometry, then shade hits with the program's `surface`/`shade`. The software composition replaces the traversal through [`program.rs:129–138`](../src/program.rs#L129-L138), so lookup improvements can benefit both paths without changing their traversal or material interfaces.

On an escaped ray, [`rl_sky`](../shaders/reflections.wgsl#L70-L73) calls `environment_reflection(direction, cone roughness)`. On a hit, [`program.rs:488–496`](../src/program.rs#L488-L496) selects open indirect state; arbitrary user shading can read diffuse irradiance and/or `indirect_radiance`. [`environment_lobes.wgsl:38–48`](../shaders/environment_lobes.wgsl#L38-L48) still performs the open-map specular lookup before adding any cache bounce. “GI off” therefore does not remove the sky lookup from reflection-hit shading.

[`program_api.wgsl:112–121`](../shaders/program_api.wgsl#L112-L121) transforms world directions to map space and calls [`scene.wgsl:253–388`](../shaders/scene.wgsl#L253-L388). The latter selects a cube face, selects roughness levels and manually cube-bilinearly filters texture-array data. **R code:** ordinary bilinear uses **4** `textureLoad`s; interpolating **2** roughness levels normally uses **8**, with extra work at edges/corners. The exact-zero blend / fully rough cases already skip the second level. GPU textures are **R code RGBA32F / 16 bytes per texel**, [`environment_gpu.rs:255–301`](../src/environment_gpu.rs#L255-L301), deliberately using `textureLoad` without optional float-filtering features ([`:211–215`](../src/environment_gpu.rs#L211-L215)).

**E upper sizing example:** at **M 1920×1080** output, if **E every pixel** launched **R code 16** valid rays and each required **R code 8** texel loads, `1920 × 1080 × 16 × 8 = 265,420,800` logical texel loads per frame. At **R code 16 bytes**, that is **E 4.25 GB** of logical fetched texels before hit shading's further lookups. This is deliberately not a DRAM bandwidth measurement: eligibility, misses, zero-weight levels, cache/coalescing and repeated addresses can reduce actual traffic greatly. Count real lookup sites and rays before using this bound in a bandwidth argument.

## Ranked causes and the cheapest discriminating test

The ranking is **E ability to explain the remaining roughly 17 ms / usefulness of a cheap test**, not measured attribution. The leading causes overlap: repeated calls, bytes, divergence and compiler pressure are different explanations of the same lookup work, so do not add their possible savings. **E upper attribution bound:** recovering the entire measured map premium would recover about **16.60 ms** of shading; no individual candidate has a measured share of that remainder. Timing switches must preserve identical geometry, materials, ray strata, cones and hit shaders unless the row explicitly labels a cost-only ablation.

| Priority | Hypothesis and source evidence | Cheapest screen / what would reject it |
|---|---|---|
| First | **Repeated manual filtering at ray misses and hit programs dominates.** The ablations above localize most of the old premium to reflection work; every hit can call more than one environment input. The constant branch replaces texture/address/filter instructions with a uniform value. | On the shipped banked layout, separately replace only escaped-ray sky reads, hit-program environment reads and primary environment reads with constants, as cost-only switches. Count calls/roughness levels in a separate diagnostic run, not the timed shader. If only primary reads matter now, reject the per-ray attribution; if both hit and miss sites matter, optimize their common lookup helper. |
| Second | **The miss-sky expression may execute even when a hit overwrites it.** [`reflections.wgsl:192–200`](../shaders/reflections.wgsl#L192-L200) initializes `radiance = rl_sky(...)` before the hit branch replaces it. Generated code may already sink or predicate the pure lookup; WGSL placement alone does not prove wasted loads. This could explain a large part only if hit frequency and actually executed discarded loads are both high. | Inspect available compiled-shader disassembly first. Then move sky evaluation into an explicit miss `else`, changing neither hit shading nor returned values. Test the software string composition too: its exact replacement template contains this code. Reject if generated code/timing is unchanged. Also screen guarding the standard primary's unused untraced-specular work when `traced.w == 1`, without removing any hit-program inputs. These are potentially image-equivalent changes; do not forecast a millisecond saving without finding executed loads. |
| Third | **RGBA32F/manual filtering throughput or latency limits the hit/miss-heavy kernel.** The common path issues the loads above; large independent-roughness banks can widen the working set. P-SHOW2 reports about **R 25 MB** of full-face banks for its independent layout, while the legacy bank addition is only about **R 0.9 MiB maximum**. They are different layouts, not one shared working-set measurement. | First vary only environment face/bank dimensions in a diagnostic input, preserving layout and shader/ray counts; then compare a finite same-layout constant-valued map with the gradient map while keeping map sampling enabled. Use texture/cache stall counters if already available. Next screen an RGBA16F upload/manual-load variant with range-aware encoding; reject if timings barely respond to dimensions/format. Halving texel bytes is **E 50% logical-byte reduction**, not a promise of half the shading time. |
| Fourth | **Residual seam/bank divergence or redundant face/level work remains.** Banking reduces seam frequency but does not delete remap branches, roughness-level selection, texture selection or repeated direction transforms ([`scene.wgsl:280–351`](../shaders/scene.wgsl#L280-L351)). Small legacy levels and independent banks have different access patterns. | Count in-face/edge/corner and one-/two-level visits separately. On a diagnostic copy, clamp all taps inside the selected face to bound seam overhead; this is visibly wrong at seams and never ships. If its timing is flat, stop seam work. Otherwise share face/address computations across the two levels and consider seam gutters; verify rotations through face edges and corners. |
| Fifth | **More texture instructions cause register pressure, spills or serialized divergent hit shading, rather than raw bandwidth saturation.** The map adds texture/address logic inside a ray-query loop with per-hit parameter changes; constant folding removes much of it. P-S4's replay results elsewhere show that apparently reusable work can lose to compiler/occupancy effects; they are not measurements of this shader. | Compare compiled register/local-memory use and occupancy for the same map/constant compositions. Isolate the common helper without changing arithmetic or sample count and examine generated code. Reject this cause if resource use and issue/stall evidence do not change. Splitting traversal/shading into queues is a later, larger option only after this evidence exists. |
| Conditional, below the common lookup causes | **Independent-layout dominant-lobe BRDF/share evaluation adds hit-shader work.** [`standard.wgsl:118–125`](../shaders/programs/standard.wgsl#L118-L125) loops over fitted lobes, reading share tables and evaluating math. This is not a CDF search and adds no geometry rays. [`environment_gpu.rs:374–397`](../src/environment_gpu.rs#L374-L397) supplies no lobes for legacy maps, so this cannot explain the banked legacy map's whole premium. | Record actual layout and lobe count. For an independent map only, force lobe count to zero in a cost-only variant while leaving prefiltered lookups unchanged. If the legacy map still has the premium, reject lobes as its cause without building anything. A speedup on the independent map identifies its own additional cost, not a reason to ship the visibly altered highlight response. |

“Mip-chain lookups in a loop” needs precision: the hot `environment_radiance` chooses at most **R code 2** adjacent levels directly; it does not walk every mip. The repeatedly executing outer loop is the **R code 4–16** glossy-ray loop, plus the hit shader's own environment inputs. The **R code 2-iteration** array loop in `environment_legacy_lod` ([`scene.wgsl:344–351`](../shaders/scene.wgsl#L344-L351)) is used by reconstruction tests, not the standard reflection call chain; rewriting that helper cannot recover this frame cost. The normal hot helper already has straight-line level reads and skips a zero-weight level. These are existing optimizations to retain, not fresh savings.

A lower-priority data-dependent branch also deserves a counter, not an immediate rewrite: [`environment_product`](../shaders/scene.wgsl#L390-L408) uses a normal-value multiplication fast path and falls back to exponent/mantissa arithmetic for extreme products. Count that fallback separately for the actual gradient and same-layout constant-valued map. Frequent fallback plus a meaningful timing-only simple-multiply control would support it; rare fallback kills it as an explanation of the large premium. Preserve saturation, exposure and HDR behavior in any retained implementation. A fast control that loses extreme highlights is not an accepted fix.

**Format changes need a quality gate.** Raw half precision can overflow bright HDR texels and change highlights; global scaling/exposure encoding must preserve dynamic range before multiplication. Hardware filtering is a separate capability/layout proposal, not something the current RGBA32F array code already uses. [wgpu's `FLOAT32_FILTERABLE` documentation](https://docs.rs/wgpu/30.0.0/wgpu/struct.Features.html#associatedconstant.FLOAT32_FILTERABLE) makes float-texture filtering optional: check the adapter and requested device feature, change compatible bindings/sampler use, and retain seam handling. **E instruction-count example:** replacing an in-face manual bilinear's **R code 4** loads with a filtering sample would reduce shader texture instructions there by about **E 75%**; hardware filtering still fetches texels, so this is not a bandwidth or millisecond prediction. Compare manual RGBA32F against manual RGBA16F first to isolate format, then compare compatible manual versus hardware filtering separately. A same-layout constant-valued **map** still exercises map indexing and texture loads; switching to the renderer's constant-sky mode does not. A compiler-folded “constant texture” replacement would invalidate that diagnostic.

Do not replace arbitrary hit shader calls with the primary material's BRDF, reuse a primary's lookup for a different hit direction, or reuse a roughness level without checking the cone. Those shortcuts would either break programmability or alter the reflected image. Count reduction is already studied in [design-glossy-rate.md](design-glossy-rate.md); keep its fixed-cone control if it is used as a cost diagnostic, because reducing count alone widens each stratum's cone.

## One short first screen

**E proposed lease: 12 minutes**, one loaded Showcase, RT first, prebuilt variants only. This is a plan for the PC unit, not work performed here. Record pass times with `RENDERLAB_PASS_LOG` and use adjacent baseline/control samples within the same process; separate cold-pipeline setup from warmed shading. Keep the actual native extent, fixed exposure, renderer settings, camera, geometry/AS and material programs identical. Identify the map layout/dimensions/level/lobe counts in the output, and log map-generation/content revision, uploads, GI queues and reflection counts once outside timed samples. Keep map identity stable through each block. The first lease should not mix a larger independent field into a legacy-layout comparison without labelling it a different input.

Use the following **E adaptive order**; each row is independently rejectable inside the same **E less-than-15-minute** lease. Do not spend the whole lease compiling every candidate before the first useful comparison.

| E screen order | Control | Confirm / kill criterion |
|---|---|---|
| Baseline | Stable banked map versus renderer constant; then the same-layout constant-valued map with map sampling still enabled. Record all named stages. | Recover the shading premium in the warmed process before attribution. If GI/upload/visibility grows instead, investigate that actual stage; if the texture-valued constant map remains slow, “bright pixels themselves trigger more rays” is unsupported. |
| Lookup sites | Map with only `rl_sky` constant; separately only hit-program open environment reads constant. Keep the primary's map inputs intact. | A large drop at a site supports optimizing it; no meaningful drop kills it as the main contributor. Primary-only constant is a tie-breaker if those do not explain the premium. These controls alter lighting and must not be accepted as fixes. |
| Discarded work | Explicit miss `else`; independently, guard standard primary untraced specular when completely replaced. | Lower warmed shading and fewer executed lookup instructions, with identical returned illumination, support the branch change. Flat results mean the compiler likely already removed/sank it or it is insignificant. |
| Common filtering | A same-layout smaller field; manual half-format versus full-format; compatible hardware-filter variant if already staged. | Lower dimension/byte cost supports working-set/throughput sensitivity. A sampler-only improvement supports instruction/address overhead. Flat format/dimension results weaken bandwidth attribution, but do not rule out texture latency or instruction limits. |
| Residual | Count seam visits and inspect register/spill/stall evidence; optional independent-only lobe control. | Pursue only a cause whose diagnostic tracks the time delta. Skip Nsight capture if tool start-up threatens the deadline; a simple paired GPU timestamp screen is enough to reject a candidate. |

**E run allowance:** reserve about **2 minutes** for load/pipeline warm-up, **6 minutes** for adjacent attribution blocks, **2 minutes** for one conditional follow-up and **2 minutes** for the potentially equivalent candidate's still/moving images and cleanup. Stop at the lease deadline if first-use compilation consumes the allowance; report “not screened” rather than comparing a cold candidate to a warm baseline. Do not add sample-count variants to this first lease. Profiler atomics, GPU readbacks and pipeline inspection belong to diagnostic blocks, not final timing samples. The same executable should switch variants while retaining the loaded scene where the existing harness permits it.

Treat altered-lighting controls as attribution tools, not acceptance images. Preserve raw HDR and the full final image for the potentially equivalent branch-only change. The quantities wanted are stable shading deltas and call/texture counts, not a faster but different sky.

**E pass/fail look-for list:** accept a branch-only optimization only if it lowers warmed shading without new seams, moving highlight pulses, lost sky detail or changes to user shader dispatch. For half-format/address variants, inspect HDR sun highlights, rough metals, mirror faces, map rotation through corners and immediate camera motion; reject white clipping, dark seams, banding or temporal sparkle. A successful RT screen still needs the same lookup change screened on non-RT, where traversal may hide or magnify its cost.

No new resampling, temporal reuse, denoising or irradiance-cache ranking is proposed by these first screens; the existing flagged sun method is unrelated and remains flagged as described in [the cut study](design-cuts.md#patent-checks-for-the-borrowed-parts). This is not a patent-clearance claim for future sampler/encoding implementations.

Reading alone cannot determine executed texture-load counts, hit/miss ratios after banking, register spills, cache behavior, the optimal texel format, or which change is visually safe. The first outcome needed is a post-banking attribution split; the old miss-ablation saving is not a budget available to claim again.

## Five-line recommendation

1. Repeat the banked-map/constant comparison in one warmed Showcase process and attribute the shading delta by lookup site.
2. Screen an explicit miss-only sky lookup and avoid the standard primary's fully replaced specular estimate, preserving hit shaders.
3. If executed loads remain costly, isolate format from sampler changes; retain HDR range and cube seams.
4. Do not chase the CPU CDF, an all-mip walk, or a map-only extra-ray/cache switch that the runtime source does not contain.
5. Keep only a measured faster variant with no visible still/motion loss; sample-count reduction remains a separate study.
