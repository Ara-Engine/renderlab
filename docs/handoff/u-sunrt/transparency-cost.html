1 Â· What changes with RT

glass_source retains hardware hard_shadow on RT. Non-RT replaces it with the cached transparent-receiver sun map; that replacement returns lit for other lights. RT's reached shadow queries terminate on the first blocker. This is extra work and a lighting difference, so substituting the non-RT branch is not a proven equivalent.

With an active RT scene, traced view and a reflective transparent program, reflect enables a separate TP2 path: rasterize world position, normal and geometric normal into three full-view targets, then dispatch an 8Ã—8 reflection kernel across the entire view. It returns early on empty pixels; populated pixels execute R1 strata and hit shading. Non-RT skips this TP2 traced-glass path. Each glass item or consecutive film run can repeat it.

2 Â· What sits inside 0.608 ms

Opaque-depth preparation; a cached sun-map render when invalidated; particle update, lighting and GPU bitonic sort; the optional RT glass lobe/trace; then pane IDs and compute shading, or raster glass/films/particles, with colour copies and resolve.

MSAA is shared: production glass uses four coverage samples on both paths. Eligible panes already shade distinct covered triangles per pixel; other glass spans seed and resolve a 4Ã— target. This does not imply four fragment-shader invocations per pixel. Object/film ordering is CPU work; particle sorting is GPU work on both paths. None has a measured sub-stage share here.

3 Â· Cheapest equivalent candidates

First candidate: skip glass runs that cannot declare a reflection lobe, then bound TP2 work to covered receivers. The current enable gate is frame-wide; a known non-reflective run need not clear and trace empty lobe targets. For reflective runs, clear and rasterize the same lobe pixels, dispatch only conservative covered rectangles/tiles, and retain exactly the same rays, hit shading and valid radiance. A nonzero origin offset and explicit validity handling are required; stale pixels and overlapping film runs must remain correct. This is a source-based opportunity, not a measured saving.

If copy/resolve dominates instead, retain draw order and 4Ã— coverage while reducing repeated full-target seed/resolve traffic through regional attachments or preserved coverage. First HDR copy is full-view; later copies already use dirty rectangles, consecutive films already share a pass, and glass spans are already capped. Ordinary scissoring alone does not remove full-target resolve traffic.

Keep sharp refraction, overlap order, off-screen reflected objects and sample coverage. Dropping MSAA, reflection strata, RT shadows or using unordered transparency would need a separate picture case; none is an equivalent established by these rows.
