## Exposure and environment limits

The first DDS transport incorrectly applied the latitude-longitude importer's Y/Z swap. `environment-v2/` corrects this: DDS/runtime sky directions use the DirectX cube basis directly, followed by the registered source-to-UE basis. A direction-coded test verifies every texel, and all source delta texels are an exact permutation. RGBA32F storage divides radiance by 64 exactly; sky intensity 64 reverses that scaling and keeps native processed sky values within FP16 range. Final DDS SHA256 is `580e46bc2d3f35ccde2a83aa068332062e4a68200ce40197355cc022ea6c9c66`. Earlier `full-*-profile-*` environment timings are superseded by the `matched-*`, then final `packaged-*` / `quiet-*` runs.

The clipped white main images are resolved. Final scene-linear mapped capture has maximum RGB 25,536, **zero nonfinite components and zero components at/above 65,504**. Manual exposure now affects the main view. Installed source explains the former failure: when the EyeAdaptation show flag is disabled, exposure compensation is forced to one. The earlier quality-zero setup did not establish the requested -14 exposure merely by reading the camera property.

The environment source, orientation and intensity now match, but its **filtering does not**. UE uses native SH diffuse and specular convolution; Renderlab uses stored diffuse irradiance and its 65-knot RLE2 field. Native BRDF/material buffers and regenerated texture mips have not been calibrated to equality. No fitted gain was applied. `photometry-v2/` compares both raw arrays with the same -14/Reinhard/sRGB display: on the common illuminated domain, UE/retained-Renderlab luminance ratio percentiles 1/10/50/90/99 are **.635 / 1.014 / 1.306 / 1.581 / 2.247**. That Renderlab image is retained 4x hard-shadow evidence, while UE uses VSM, so this is a diagnostic, not a photometric acceptance score. Native UE filmic PNGs also use a different display curve. **End-to-end radiance parity remains a blocker.**

Other known mismatches are the small sun-color quantization, Nanite compression/LOD, texture mip generation/sampler details, UE's deferred BRDF versus Renderlab's composition, and native shadow receiver bias, sample placement, filtering and histories. The reference retains Renderlab's geometric-normal offset and projected ray interval. Those are not an unbiased physical oracle for UE's receiver/filter estimand. UE's source default max RT normal bias is .1 cm, but this CVar was not separately queried in this window, and matching its scalar would not match the complete offset/ray interval. Large residual errors below must not be attributed entirely to geometric detail, nor presented as engine-wide quality superiority.
