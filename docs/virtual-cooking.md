# Virtual cooking and CPU proofs

Unit A uses cooker-only meshopt exactly 0.7.0 / packaged meshoptimizer 1.3. Source grounding is the package's `src/clusterlod.rs`, `vendor/demo/clusterlod.h` and generated configuration bindings. The wrapper passes borrowed callback arrays; cooking copies indices and scalar metadata before return. Root/independent review and GPU acceptance remain separate.

Pinned raster defaults use max 128 vertices/triangles, min 42 triangles, target partition size 16 (upstream can exceed target by one third), spatial partitioning, flex clustering/split factor 2, optimized cluster order level 1, simplification ratio 0.5 and stuck threshold 0.85. Previous error merge factor is 1, additive factor 0. Regular attribute-aware simplification is selected: permissive mode and both permissive/sloppy fallbacks are disabled. Error clamping and edge-length error limiting are disabled, avoiding reduced errors that conceal attribute costs. Border dilation is disabled and unsupported by the safe immutable-position wrapper. Normals XYZ, UV XY and linear RGBA all have weight 1 and protection mask 0x1ff. Positions and all retained vertex attributes keep their original f32 bits. A supported settings variant uses max 64 vertices/triangles with its matching raster defaults. No silent fallback accepts unsupported source content.

Each primitive/material subset is cooked separately. Shared position bits across independently cooked primitive boundaries are explicitly locked; signed zero is canonicalized only for recognizing shared positions. Within a primitive, regular simplification and the full attribute protect mask preserve discontinuities. Upstream's group-boundary lock propagation keeps matching positional edges during simplification. Page packing deduplicates source vertices within each page, duplicates across pages/LOD representations as needed, and packs terminal fallback clusters first. No quantization, mesh/texture compression or full-detail runtime vertex fallback is introduced. The accepted M3 source import/material/texture/placement rules remain unchanged.

Virtual cooking additionally rejects position, normal or UV components with absolute magnitude above 1,000,000 before calling the C++ builder, bounding its floating-point intermediates. This cooker-only supported domain does not narrow M3 decoding or rendering. The bound is included in the algorithm identity; it is a numerical guard, not an error theorem for arbitrary geometry. Invalid/degenerate hierarchies still fail package validation.

The cache key includes algorithm identity (`virtual_cook::ALGORITHM`), virtual version, cluster settings, every prepared/virtual limit and complete RLA1 source bytes. Exact dependency archives are in Cargo.lock. Algorithm/default changes require identity updates. The cooker retains the full-detail reference as a separate file and publishes only the virtual metadata plus immutable pages. M3's same-directory create-new temporary/write/sync/rename primitive publishes complete entries. Every page and metadata blob is reread, digest-checked and decoded before key/current manifests are published. Warm lookup still hashes source and verifies/decode-checks every page; it performs no clustering. Partial/corrupt entries are diagnosed, never hits, and deterministic recooking repairs content-addressed entries. Failure preserves the prior current manifest. Same-filesystem rename and durability limitations match asset-format.md; this is integrity against accidental corruption, not authentication or a backup system. Garbage collection and concurrent hostile mutation are outside this boundary.

Reproduce on the Windows development host, with no active quiet-window owner or foreground gameplay:

```powershell
cargo run -j 2 -p renderlab-cook --locked -- m4-register measurements/m4-cook/new-registration
cargo run -j 2 -p renderlab-cook --locked -- m4-cook measurements/m4-cook/new-registration/closed-sphere.rla measurements/m4-cook/cache measurements/m4-cook/sphere.manifest
cargo run -j 2 -p renderlab-cook --locked -- m4-inspect measurements/m4-cook/cache measurements/m4-cook/sphere.manifest
cargo run -j 2 -p renderlab-cook --locked -- m4-prove measurements/m4-cook/cache measurements/m4-cook/sphere.manifest closed
powershell -NoProfile -File scripts/m4-cook-check.ps1
```

The helper uses a fresh cache/evidence directory; checks fmt, locked workspace/all-target compilation, Clippy warnings, all nonignored CPU tests, dependency isolation including build edges, deterministic regeneration, dense cold/warm/settings/source changes, page corruption rejection/repair, partial current manifests and independent Python binary/page inspection. It saves source/executable identities, method/host/load information and sampled process memory. One run/state is descriptive, not a comparative latency verdict. Initial registration is preserved even when generator source formatting or executable identity changes.

Focused proofs cover chain, multiple owners, shallow terminal and diamond DAGs across 58,040 small availability/capacity cases. Legal-cut replay removes every incoming shard exactly once before emitting a fine group. An independent oracle directly implements upstream's owner-error > threshold AND (original OR refined-error <= threshold) rule. It never calls selection. The real 24-subdivision closed sphere enumerates all legal activation sets; dense fixtures sample scalar/camera-derived cuts, finite caps and unavailable pages. Exact bit-position welding treats UV/material wedges as one geometric point for topology only: every closed-cut undirected edge must occur twice with opposite orientation. No epsilon welding hides cracks. The wavy sheet/fins are intentionally open, so closed-edge criteria apply only to the sphere. GPU silhouettes/material/UV/normal continuity and actual moving frames remain required; CPU topology does not certify image quality.

Cooking memory is bounded by admitted source sizes and explicit output group/cluster/index/page/metadata caps. Rust and upstream C++ scratch, parser state, page duplication and reread verification exceed logical source bytes; default caps are not a strict process-RSS limit. Counters expose source/packed/unique vertex counts, callback index bytes, peak single-primitive position/attribute bytes, payload/padding, root minimum and metadata host storage. The proof harness retains decoded pages and positional-edge hash maps and is not the runtime memory policy. Runtime async IO, GPU buffers, retirement, multi-instance pool admission, complete images and comparative performance are Unit B/C gates. Nothing here establishes Nanite superiority or M4 completion.
