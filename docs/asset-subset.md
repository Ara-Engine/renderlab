# Static embedded GLB subset

`renderlab-cook` accepts GLB 2.0 with asset version 2.0, exactly one embedded buffer, one JSON chunk followed by one BIN chunk and no trailing/unknown chunks. It uses `gltf = 1.4.1` with defaults off and only `utils`; no import helper resolves resources. `image = 0.25.10` has defaults off and only PNG/JPEG. Unsupported content returns a diagnostic. This document describes prepared data, not implemented GPU shading.

Supported geometry is static triangle-list primitives, indexed U8/U16/U32 or nonindexed, with ordered primitive material assignments. POSITION and supplied NORMAL are nonnormalized float VEC3. UV0 is float VEC2 or normalized unsigned U8/U16 VEC2. COLOR_0 is float or normalized unsigned U8/U16 VEC3/VEC4; RGB gains alpha 1. Vertex colors are linear. Missing UVs become [0,0] only for untextured primitives; every textured primitive requires UV0. Missing colors become linear white.

Supplied normals remain unchanged after finite/nonzero validation. When normals are absent the default is flat face normals, using f64 edge/cross/normalization, expanding indexed vertices into independent triangle vertices and sequential indices. Degenerate triangles cannot generate normals and fail. `--reject-missing-normals` rejects absence instead. Supplied-normal degenerates are retained. No welding, simplification, tangent generation or vertex compression occurs.

All bufferView spans are checked against both the embedded buffer's declared length and actual BIN bytes. Up to three BIN padding bytes are allowed. Every accessor must have a bufferView, positive bounded count, checked offset/last-element extent, and appropriate component alignment. A declared stride must be 4 through 252 bytes, divisible by four, and large/aligned enough for its element. Index accessors cannot be strided. Attribute counts must match POSITION exactly. Sparse/matrix accessors and unsupported normalized component/type combinations are rejected before reader use. Utilities are used only after these checks; their validation is not the allocation policy.

The explicit default source caps are 64 MiB file, 8 MiB JSON, 16,384 nodes/edges, hierarchy depth 128, 256 images/scenes, 65,536 accessors/views and 4,096 samplers. A JSON structure walk has a 500,000-value work cap; serde_json also retains its default recursion-depth check. The bounded JSON parser allocates its tree before the structure walk, so the JSON-byte cap is the initial parse-memory bound, not a strict process-RSS cap. Prepared caps are in asset-format.md. All geometry uses aggregate count and byte budgets. Texture and geometry logical output bytes share the prepared budget before geometry allocation.

Node hierarchy transforms are flattened in source scene depth-first order. Repeated nodes refer to the same prepared mesh. Use the explicit default scene, or the sole scene if no default exists. Unselected scenes are not placed; all source meshes/materials are still prepared and all node transforms/hierarchy edges are validated. Every source and composed placement must be finite nonsingular affine. Cycles, duplicate parent edges, multiple parents, scene roots with parents and duplicate selected roots are rejected. A matrix cannot coexist with TRS. Quaternion squared length must be within 1e-4 of one. Transform composition accumulates in f64 and rounds each flattened level to f32. Mirroring, nonuniform scales and affine matrices are accepted. Prepared validity alone makes no normal-rendering claim for ill-conditioned transforms. M3 rendering additionally restricts single-sided materials and normal diagnostics to a max-element condition estimate at most 10,000. A cooker-valid highly anisotropic asset can therefore be refused by the viewer, including after rotation changes that estimate; the current viewer exits with a diagnostic. Raw double-sided unlit rendering accepts general finite matrices.

Supported materials are opaque core metallic-roughness. Linear base-color RGBA, metallic/roughness factors, optional base-color/MR textures, double-sidedness and declared samplers are preserved. Texture coordinate set must be zero. Explicit wrap, mag, min and mip choices are retained. Missing sampler filters choose linear mag and linear/trilinear min; missing wraps choose repeat. These are Renderlab's documented choices for glTF's unspecified filters. No lighting is implied by stored MR factors.

Embedded images must declare PNG or JPEG with a matching byte signature. PNG/JPEG dimensions and native output size are obtained under image decoder limits before allocating pixels. Maximum dimension is 4,096. The cumulative image decode charge (native decoded bytes plus RGBA8 conversion bytes, including role-specific decodes) is 128 MiB; prepared mip bytes are independently charged to the shared 256 MiB prepared budget. `image`'s dimension limits are strict, its internal allocation limit is best effort; bounded compressed file bytes, dimensions and output budgets supplement it. Process RSS includes parser/codec scratch and duplicate validation buffers and is not capped at 256 MiB. No shell subprocess reads source resources.

Base-color RGB stays sRGB-encoded RGBA8 with linear alpha. Metallic/roughness is numerical linear RGBA8; G means roughness and B metallic, multiplied by material factors. A source image used for both roles produces separate role-correct chains. Same-image/same-role references share one texture even when samplers differ. Images are decoded on demand for used material roles. The full mip chain reduces dimensions by floor division to 1x1. An area box filter includes fractional odd-edge coverage. RGB filtering for base color converts sRGB to linear before averaging and back afterward; alpha/data average numerically. Each level is quantized to RGBA8 before producing the next. PNG/JPEG embedded profile/text metadata is not imported, and no alpha premultiplication is performed because alpha rendering is unsupported.

Rejected features include any nonempty extension declaration/object, external/data image or buffer URIs, skins, animations, morph targets/weights, nontriangle topology, sparse or matrix accessors, tangents, joints/weights, additional UV/color sets, normal/occlusion/emissive textures, nonzero emissive factors, nonopaque alpha modes and camera nodes. Compressed geometry/textures and texture transforms require extensions and fail. Even optional extensions are rejected instead of silently changing appearance.

Ignored metadata is names, extras (including application-defined data), asset generator/copyright, bufferView target hints and accessor min/max (actual geometry is validated independently). Opaque alpha cutoff is irrelevant and ignored; stored base/vertex/texture alpha does not enable transparency. Unreferenced camera definitions and unselected scene metadata are not consumed. Unknown nonextension JSON fields follow the upstream schema's ignore behavior; applications must put visual extensions in the glTF extension mechanism. No normal mapping, material graph, lighting, transparency, animation or virtual geometry is part of unit A.

Both generated fixtures and their provenance are described in `assets/PROVENANCE.md`. No imported artwork or project license was selected.
