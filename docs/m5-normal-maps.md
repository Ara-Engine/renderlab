# M5 normal maps

This unit adds normal-map rendering to prepared regular meshes and virtual pages. CPU checks, four focused normal GPU gates and fifteen retained material, lighting, virtual and shadow gates pass with active Vulkan validation. Actual BRDF-lit fixture and private boulder images were inspected at 1x and 4x, including three-pose motion. Gloss motion quality remains open. This is a verified integration checkpoint, not M5 completion or an Unreal comparison.

Independent review found a generated-tangent convention error before this checkpoint. Root corrected it against the owned Blender 5.1 export and the [MikkTSpace glTF conversion guidance](https://github.com/donmccurdy/mikktspace-wasm#other-considerations). Negating generated W preserves Mikk's original UV precision and agrees with authored glTF frames. The importer also follows the [glTF missing-normal rule](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#meshes) by ignoring provided tangents when it generates flat normals. The cache recipe changed so incorrect generated frames are not reused. Focused authored/generated and missing-normal tests pass, followed by the four normal GPU gates on regenerated fixture assets. Earlier scan captures used the compensating green flip and remain historical evidence, not proof of a correct importer.

## Asset and import records

`Vertex` remains 48 bytes. `Primitive::tangents` is an optional `TangentStream` with `TangentBasis::Authored` or `MikkTSpace` and one XYZ+W value per vertex. The stream shares the primitive's remapped vertex and index domain. Frame validation requires finite unit XYZ, a unit orthogonal normal, W exactly -1 or +1, matching counts and one W sign per triangle. The squared-length and orthogonality tolerance is `2e-4`.

`Material::normal_texture` stores a texture index, exact sampler and finite XY scale. `TextureRole::NormalLinear` denotes linear RGB XYZ with positive Y along `W * cross(N,T)`. Negative and zero scale are supported. Normal mips use the existing decoded-vector area filter and normalization helper. Scale remains material state. There is no variance preservation or roughness compensation.

The existing cooker recipe remains the default. `Settings { normal_maps: true, ..Default::default() }`, or `renderlab-cook cook SOURCE CACHE MANIFEST --normal-maps`, enables the extended recipe. The importer preserves valid authored tangents when normals are present. Without normals, it ignores authored tangents before generating flat normals, as glTF requires. Normal-mapped primitives without usable authored tangents use the pinned MikkTSpace helper and retain its vertex splits. Generated W is negated to convert MikkTSpace to the glTF image convention; authored W is preserved. This matches the owned Blender glTF plane export. Conversion happens after generation, avoiding precision loss from replacing small UV coordinates with `1-v`. Authored tangents are also preserved when a material has no normal texture. Unsupported texture transforms, extensions and texture coordinate sets produce source errors. Only UV0 is supported. The existing missing-normal policy still applies before tangent preparation.

Admission charges final tangent bytes and conservatively bounds live source, expanded corner and output arrays before collecting tangents. Normal preparation charges decoded image storage, intermediate f32 mip vectors and exported mip bytes. These are logical array budgets, not a measurement of allocator or MikkTSpace internal scratch overhead. Limits remain configurable through the existing APIs and tooling.

## Binary and cache versions

The later [adjacency preparation format](asset-format.md#cache-identity-and-publication)
extends current regular cooker output to schema/manifest 3 and invalidates lookup
keys. Schemas 1–2 remain readable. The version-2 description below records the
original normal-map checkpoint.

Unextended assets still emit RLA1 and RLG1 bytes. A checked-in triangle golden was generated by the original asset encoder at `0190bf012ec7a8c7ef4be998aa8c28bd5481047e`. The frozen default regular cache-key test remains unchanged and passes.

RLA2 and RLG2 add a basis tag and tangent count after each primitive's material, vertex count and index count. Tags 0, 1 and 2 mean absent, authored and MikkTSpace. The base stream is followed by the optional 16-byte tangent stream, then u32 indices. The tangent count must be zero for absent streams and exactly the vertex count otherwise. RLA2 appends a normal reference and scale to each material and adds texture role 2. An absent normal reference has canonical scale 1. Versions, tags, counts, references, finite values, extents, truncation and trailing data are checked explicitly.

The extended regular recipe uses `normal-v2/keys` and manifest version 2. Content-addressed asset and geometry entries retain their existing directories so identical unextended geometry can be reused. The corrected recipe identity includes generated-W conversion, missing-normal tangent handling, MikkTSpace version, frame tolerance, degeneracy threshold, positive-Y convention, mip normalization and XY scaling policy. Legacy settings keep the existing keys and manifest version 1.

RLV2 adds a tangent basis tag to each page record. Pages contain base vertices, optional tangents and indices, with zero padding to 64 KiB. A tangent page charges `64 * vertices + 4 * indices` payload bytes. Material references that need normals require tangent-bearing pages. RLV1 pages and resources still decode with absent tangents and normal textures.

Virtual cache manifests, keys, packages and normal-bearing pages use `virtual-v2`. The virtual recipe names the 13 attributes, source-frame subset simplification and locked tangent seams. Unextended sources retain the existing virtual recipe and `virtual-v1` namespace. A basic page in a mixed v2 package is also published in the existing v1 page directory so the existing standalone page API can reuse that content by hash.

Virtual simplification retains original indexed frames and adds all four tangent components to protected attributes. Coincident position records with different normal, UV or tangent frames are locked. Page packing separates absent, authored and generated streams and recalculates capacity before append. It does not average W signs or synthesize a cheaper frame. Actual normal-bearing dense sphere tests check every packed vertex/frame pair against its source and check material assignment after simplification. No coarser normal-mapped virtual level has been rendered in this evidence. The GPU equality test uses the finest level (`error_pixels: 0`), and the boulder uses only the regular path. Coarse-level shading and the reduction cost of locking scan-atlas seams remain unverified.

## Runtime and shader

`Renderer::try_upload_mesh_with_tangents(&MeshData, Option<&TangentStream>)` uploads a validated optional stream. The existing `try_upload_mesh` remains the basic upload API. This explicit adapter preserves the frozen lighting fixture and existing raw mesh callers without adding a mandatory dummy stream. Prepared regular and virtual adapters use the tangent-aware path. A regular draw with a normal material and no tangent buffer returns an error.

`MaterialDescriptor` adds `normal_texture` and `normal_scale`. Group 2 uses a 48-byte uniform, with scale at byte 32 and the normal flag at byte 36. Normal texture and sampler use bindings 5 and 6. Unmapped materials retain a flat linear normal binding. Texture roles and renderer identity are validated before allocation. Owned materials retain all three textures and samplers. Tangent buffers use the existing owned-buffer lifetime, upload admission and submission tracking.

The camera pipelines have basic and tangent variants. The optional tangent stream uses buffer slot 2 and location 5. Instance IDs remain at slot 1 and location 4. All four camera pipelines, the presentation pipeline and M6's base-only shadow pipeline compile and install together from the single `scene.wgsl` module. A failed tangent or shadow variant rejects the entire candidate. Diagnostic values 0 through 3 keep their meanings, including the authored-normal diagnostic.

Lit shading computes `N = normalize(A^-T n)` and orthogonalizes `A t` against N. After interpolation it orthogonalizes T again, then computes `B = W * sign(det A) * cross(N,T)`. The sampled linear normal scales XY and normalizes before frame conversion. The scaled calculation avoids overflowing finite material scales by construction; device tests cover scales -1, 0 and 1, not the extreme finite range. Cancelled sampled vectors use positive Z. Cancelled interpolated normals use a derivative face normal with viewport-Y and source-winding correction. This also corrects the previous unmapped cancellation fallback. There is no numerical oracle for varying interpolated frames yet; the numerical frame test uses a uniform per-vertex frame. A source-back, double-sided face reverses the complete perturbed frame. Degenerate interpolated tangents use a finite orthogonal axis.

The virtual resource ledger includes tangent GPU buffers, CPU-ready capacity and staging bytes. The existing 64 KiB residency reservation, retirement rules and last-use stamps remain. Material and light edits do not require mesh uploads or per-frame completion waits.

## Verification boundary

The original integration passed 57 asset and cooker CPU tests and 49 renderer CPU tests. After the convention correction, all 59 asset and cooker CPU tests plus the compile-fail doctest pass. New tests cover the actual owned GLB import, exact authored/generated correspondence, linear mips, negative/zero scale, sampler preservation, unsupported inputs, intermediate budgets, RLA2 corruption/truncation, dense virtual simplification, page counts and cache repair. The correction adds the owned Blender-exported plane and missing-normal tangent cases. Workspace all-target Clippy with `-D warnings` and formatting pass on the corrected source. The renderer implementation is unchanged from the integration checks; the shader changes only a comment. All four normal GPU gates were rerun after regenerating the fixture with corrected tangent frames.

The `normal_render_fixture` cooker example produces source GLB, regular payloads and virtual caches for mapped, flat, unmapped, negative-scale and zero-scale cases. Four ignored `gpu_normal_maps_` tests pass on the RTX 4070 SUPER. They cover the full-image HDR frame oracle across 1x/4x transforms, handedness and source sides, cancellation fallback, tangent reload recovery, exact resident regular/virtual images, mixed basic/tangent draws and normal texture/material/tangent replacement. Each replacement kind observes incomplete prior frames at least eleven times per AA count, with bounded ownership. Foreign normal textures and draw resources, and mapped materials without tangent streams, reject without uploads. A separate actual-occlusion mask test proves that strong normal perturbation leaves the geometric shadow mask identical.

Flat RGBA8 normals have quantization error because 128 decodes to approximately +0.00392. Across three fixture poses at 1x and 4x, flat-versus-unmapped HDR error stays below the declared `.015 + .01*abs(unmapped)` tolerance. The observed maximum is .0029296875; zero scale exactly matches unmapped. Mip renormalization loses variance and has no roughness compensation. On the roughness-.08 fixture at 4x, adjacent mapped frames have visible-pixel mean absolute HDR changes of .0400 and .0361, with localized maxima 128 and 94.5. Unmapped changes are .00220 and .00254. These raw screen-space changes include physical view response and edge sampling. They do not isolate aliasing error or certify temporal quality.

The integrated M6 implementation retains group 3 bindings 4 and 5 for shadow depth and records, separate from the normal extensions in group 2. Camera and shadow vertices both use `world_position`. Shadow raster uses only the base stream. Receiver bias and comparison use the unchanged derivative geometric normal, independently of normal-map perturbation and its source-oriented cancellation fallback. The six-query flight layout, complete caster slots, source-sided shadow discard, page stamps and transactional submission remain intact. Existing shadow tests and expectations are unchanged. The known 1024 quarry failure and residual 4096 speckle remain open.

`examples/m5-normal-maps.rs` captures prepared inputs without a window and optionally alternates a mapped asset with an otherwise identical unmapped control. It records HDR, complete display images, camera, light, input identities and separate CPU admission, mesh, presentation and render-span observations. The private `xb5gbjo` boulder retains all 1,001,334 triangles, 504,591 tangent vertices and three 4K texture chains. Source normal red correlates .310 with negative bump-U; green correlates -.321 with negative bump-V over 2,604,821 sampled texels. The historical private conversion flipped green to compensate for the generated-frame convention defect; the correlation did not justify blaming the source map. The correction retains the source green convention and converts generated W instead. Historical mapped-versus-unmapped luminance MAE is about 1.7% of mean luminance, with roughly 8% of visible pixels changing by more than 5%. The images establish a small effect and complete geometry, not correct orientation or strength. The exporter comparison provides the convention evidence.

One retained bounded 4x boulder sample alternates off/on/on/off at each of three poses. Six mesh-pass observations per state have medians .593 ms unmapped and .775 ms mapped, with ranges .573-.815 and .660-1.194 ms. The GPU difference is inconclusive as a stable feature cost. CPU admission in the same six mapped samples is .774-1.018 ms versus .378-.617 ms for unmapped samples (medians .823 and .419 ms). The increase occurs in each pair; its cause is unprofiled and must not be attributed to normal shading from these measurements. Both cases draw all source triangles, retain identical tangent geometry and upload no geometry during samples. The optimized Vulkan run has active validation, uncontrolled background contention and no hardware-limiter profile. These paced passes exclude uploads and native presentation, and do not measure pipelined throughput.

Root recooked the boulder without the compensating green flip and inspected the full corrected 960x640, 4x image. Against the historical compensated pose, only 163 of 1,843,200 display channels differ, each by one 8-bit code. Maximum absolute resolved HDR difference is .0004272461, with no non-finite values or resolved saturation. This confirms preserved appearance for that pose, not a new motion or physical-strength claim. The source GLB preparation took 13.041 s, cooking 46.023 s and the one-frame capture process 1.590 s. These single wall-clock observations include tool/process work and are not frame times or development-loop medians.

The correction's first device run failed on dangling third-party PRISM/Overwolf Vulkan layer registrations. The rerun used the project's existing empty implicit-layer path, retained explicit Khronos validation, and passed all four gates with zero validation errors. The fresh scan also records an active validation layer and zero errors. Both failed and successful logs are retained under `.refs/m5-normal-correction/`.
