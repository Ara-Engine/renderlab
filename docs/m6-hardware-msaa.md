# Optional hardware directional shadows at 4x MSAA

The optional regular-geometry hardware path now accepts `RendererOptions.samples = SampleCount::Four`. Each covered sample queries visibility from its own perspective-interpolated world position. This bounded M6 unit preserves opaque double-sided affine geometry and directional hard shadows. Virtual geometry, single-sided query culling, transparency, local shadows, and softness remain outside this unit. M6 and the matched Unreal quality and 2x performance gates remain incomplete.

The existing sample-count enum owns the choice. No new public lighting field, binding, dependency, render pass, or renderer architecture was added. The acceleration structure remains at group 0 binding 2. Environment bindings remain unchanged. AS ownership and terminal frame-error behavior are unchanged.

For 4x hardware shader composition, the existing `VertexOutput.world` declaration gains `@interpolate(perspective, sample)`. Both vertex output and fragment input use that struct. `fs_lit` passes `input.world` directly to the existing visibility query. The derivative geometric plane still determines the light-facing origin offset. Authored normals and normal maps never determine that offset. Other interpolants retain their existing sampling qualifiers.

The smallest alternative, invoking a fragment once per sample while keeping a centre-interpolated world position, would repeat the same ray. The retained test explicitly constructs that impostor and rejects it. Sample interpolation changes the receiver value as well as the execution frequency. The [WGSL interpolation rules](https://gpuweb.github.io/gpuweb/wgsl/#interpolation) define that behavior. The [Vulkan sample-shading rules](https://docs.vulkan.org/spec/latest/chapters/primsrast.html#primsrast-sampleshading) require sample interpolation to affect shader results when the decorated input matters to the output.

The installed dependency sources establish the native implementation. All versions are 30.0.1. Naga's `src/valid/interface.rs` requires `Capabilities::MULTISAMPLED_SHADING` for sample interpolation. Its `src/back/spv/writer.rs` emits SPIR-V `Sample` and requires `SampleRateShading`. `wgpu-naga-bridge/src/lib.rs` maps that capability from `DownlevelFlags::MULTISAMPLED_SHADING`. The Vulkan HAL's `src/vulkan/adapter.rs` exposes that flag from `sampleRateShading`, enables the device feature, and permits the corresponding SPIR-V capability. Its `src/vulkan/device.rs` does not set a pipeline-wide minimum shading fraction. The shader's used sample-qualified world input supplies the per-sample requirement.

Callers still negotiate `EXPERIMENTAL_RAY_QUERY`, AS limits, and wgpu's experimental safety acknowledgment. 4x additionally needs the adapter's sample-rate shading capability and existing format/resolve support. There is no additional `wgpu::Features` bit to request for sample shading. The evidence example checks the adapter downlevel flag. Source inspection establishes that shader/pipeline validation rejects unavailable capability transactionally; no device lacking that capability was tested. A sample qualifier makes the whole lit fragment body execute at sample frequency, so its cost includes more than the visibility query alone.

The existing mesh pass writes multisampled RGBA16F and resolves it at the end of that pass. The later presentation pass tone maps the resolved HDR value. Queries therefore happen before resolve, and resolve happens before tone mapping. The analytical half-visible pixel resolves to HDR 0.5 and display code 85 in the linear-unorm test target. Averaging already tone-mapped binary visibility would produce a different result.

One-file `scene.wgsl` reload remains available. Only the optional 4x module receives the interpolation qualifier. Its receiver declaration must retain the existing spelling `@location(4) world:vec3<f32>,`; a missing or duplicate declaration rejects reload. Affine functions remain protected, with CRLF normalized inside their comparison. Ordinary material and lighting edits remain reloadable. The installed shader hash includes the composed module and thus its sample qualifier. Editing the embedded hardware helper or composition logic still requires a Rust rebuild.

This unit also renames `HardwareShadowStats.actual_as_bytes` to `observed_as_bytes`. It reports named allocator attribution, not physical residency. Allocator labels now contain a per-renderer nonce and a local allocation sequence, so two renderers sharing a device do not share label names. The reload test now moves the blocker into the light path after a corrected reload and requires positive occlusion.
